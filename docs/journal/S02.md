# S02 · 透明浮层：SpringBoard 上挂独立 UIWindow + 可拖动方块

- 阶段：S2（计划 3 人日，实际 1 个工作日内 CI 出包）
- 状态：**代码侧 CLOSED，真机现象待操作员确认**（见 §5）
- 前置：S1 已关闭；S1 真机验收通过（见 §2.0）

## 1 目标

S1 只证明「注入得进去」。S2 要把后面所有渲染的地基打出来，验收四条：

1. 能在 SpringBoard 的 `UIWindowScene` 上再挂一个**自己的** `UIWindow`，不抢 App 的窗口；
2. 这层能浮在桌面图标、Dock、App 界面之上，但**不盖**系统弹窗（来电/控制中心/通知）；
3. 背景全透明，**只有方块区域吃触摸**，其余点击穿透给下面；
4. 能拖、能点、位置能落盘，旋转/尺寸变化后按比例回到正确坐标，且永远不进系统手势区。

### 2.2 关键设计决定

- **窗口层级** `UIWindowLevelStatusBar + 100`：高于 App 与状态栏，低于 Alert/来电（`UIWindowLevelAlert`），所以系统弹窗永远在上面。
- **穿透实现**：`DSHPetWindow` 重写 `hitTest:withEvent:`，命中 rootViewController.view 或方块外一律返回 nil。
- **手势保护区**（对齐方案 §15.1）：拖拽夹取时左右各留 20pt、顶部 40pt、底部 34pt，方块永远压不到系统手势带。
- **relayout 不用通知**：iOS 16.5 SDK 没有 `UIWindowSceneDidUpdateCoordinateSpaceNotification`（CI 实测编译失败），改为重写 `DSHPetWindow.layoutSubviews`，旋转/分屏/安全区变化都会走到，且不依赖 SDK 版本。
- **层级后备**：若真机上被 Dock/图标盖住，说明 SpringBoard 桌面本身在更高层级，则改用 _sbWindowScene 上的 _statusBarWindow 同级或直接提 UIWindowLevelAlert - 1（仍低于 Alert，来电/授权框不受影响）。这一条不预做，等 S2 真机第 1 条结论。
- **配置落盘** `/var/mobile/Library/DSHPet/config/ui.json`：`enabled/size/centerX/centerY/taps/windowLevel`，坐标存**归一化比例**（0–1），所以换分辨率不会跑偏。

## 7 真机反馈与修复（S2 阶段内，不计新阶段）

操作员装机 `v0.1.0-15` 后回传两条现象：**① 其它都正常；② 横屏时绿方块不显示，转回竖屏又正常；③ 旋转过程中屏幕有黑边/阴影残影**。

### 7.1 横屏不显示

- 原实现：`relayout` 里 `_window.frame = _scene.coordinateSpace.bounds`。
- 根因：旋转时 UIKit 已让挂在 scene 上的 window 自己跟过去，我们再设一次 frame 等于**转两次**，方块被转到屏幕外；转回竖屏又对上了，所以"只有横屏丢"。
- 修法：`relayout` 只用 `_window.bounds` 算坐标；仅当 window 尺寸明显落后于场景（且呈 90° 互换）时才修正一次（`staleFixed` 会写进日志）。另加 `UIDeviceOrientationDidChangeNotification` + 0.45s 延迟校正，覆盖 `layoutSubviews` 早于最终尺寸的情况。

### 7.2 旋转黑边/阴影残影

- 根因：SpringBoard 旋转时会对每个窗口做快照再动画，我们这层额外窗口参与其中，就会留下黑边或阴影残影。
- 修法：旋转期间整层 `alpha = 0`（`CATransaction` 关隐式动画）→ 0.45s 后 relayout → `alpha = 1`；并把窗口层强制彻底透明：`layer.opaque = NO`、`backgroundColor = clear`、`allowsGroupOpacity = NO`、`shouldRasterize = NO`、`shadowOpacity = 0`。

### 7.3 顺带修的两处

- 保护区改用 `safeAreaInsets`（与 40/34/20 取更大值），带刘海/Home 条机型不再贴着系统手势。
- `CGRect` 成员写错（`sb.height` 应为 `sb.size.height`）导致一次 CI 编译失败，已修。
