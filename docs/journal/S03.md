# S03 宠物本体上屏（AVPlayerLayer）

- 阶段：S3 第一版
- 起止：2026-11-15 18:30 → 18:55（Asia/Shanghai）
- 版本：`0.1.0-32`

## 1 目标

把 S2 的绿色方块换成真正的宠物画面：`AVPlayerLayer` 播透明视频，循环播放，尺寸可随配置缩放。

## 2 做了什么

| 文件 | 内容 |
|---|---|
| `packages/ios/DSHPetPlayer.h/.m` | 播放器单例：扫素材目录 → 建 `AVPlayerItem` → `AVPlayerLayer`（`ResizeAspect`、透明底、`opaque=NO`）→ `AVPlayerItemDidPlayToEndTime` 回 0 循环；`play/pause/setDisplaySize/syncLayerFrame`；无素材时记 `player-no-asset` |
| `DSHPetOverlay.m` | 宿主 view 尺寸改为 `size × size*1215/2160`（与上游 2160×1215 素材同比例）；`attachToHostView:` 把播放层挂上去；有素材就把方块背景/圆角/边框清掉，没素材保留占位方块 |
| `packages/ios/Makefile` | 加 `DSHPetPlayer.m`、`AVFoundation`；顺手把之前 GBK 乱码注释重写为 UTF-8 |
| `packages/ios/layout/var/mobile/Library/DSHPet/assets/demo.mov` | 内置演示素材（见 §3） |
| `layout/DEBIAN/postinst` | 建 `assets` 目录、`chown mobile:mobile`、权限 755 |

素材优先级：`main.*` → 任何非 `demo.mov` → `demo.mov`。以后 S9 下载器把整包灌进来时，只要文件名不是 demo 就会自动顶掉演示素材。

## 3 内置 demo.mov 是怎么来的

设备上没有任何素材，装机后什么都看不到，无法验收。所以本地生成了一段真·透明视频：

- 40 帧 PNG（540×304，PIL 手绘：青蓝渐变身体、呼吸缩放、每 2 秒眨一次眼、腮红、嘴），
- `ffmpeg -c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le -alpha_bits 16 -vendor apl0` → **ProRes 4444 with alpha**，
- 体积 2.7MB，打进 deb 后（xz）整包 557KB。

选 ProRes 4444 而不是 HEVC-alpha：HEVC 带 alpha 需要 VideoToolbox 编码器（只有 macOS 有），本机编不出来；ProRes 4444 的 alpha 是标准特性，A16 硬解没问题，且能直接验证"透明通道 + AVPlayerLayer"整条链路。

## 9 首轮真机失败：绿方块还在（0.1.0-32）

### 9.1 现象

装 0.1.0-32 后桌面仍是一个绿色半透明大方块（没有视频），且方块宽到接近整屏。

### 9.2 根因一：rootless 前缀把素材装到了错地方

`layout/` 下的路径在 rootless 包里会被整体加 `/var/jb` 前缀。我把素材放在
`layout/var/mobile/Library/DSHPet/assets/demo.mov`，安装后实际落到：

```
/var/jb/var/mobile/Library/DSHPet/assets/demo.mov   ← 多了一层 /var/jb
```

而代码读的是 `/var/mobile/Library/DSHPet/assets` → 目录不存在 → `player-no-asset` → 退回占位方块。

修法：

- 随包素材改放 `layout/Library/Application Support/DSHPet/demo.mov`（即 `/var/jb/Library/Application Support/DSHPet/demo.mov`），**非** `/var/mobile` 下；
- `postinst` 把它拷到运行目录 `/var/mobile/Library/DSHPet/assets/demo.mov`（用户可写、Filza 能替换），且不覆盖已有的 `main.mov/main.mp4`；
- 代码两条路径都扫：先运行目录，再随包目录兜底。

### 9.3 根因二：CI 的 dpkg-deb 兜底掩盖了编译失败

0.1.0-32 的构建 run 实际是**红**的（`DSHPetPlayer.m` 里 `kPetAssetDirFallback` 未声明）。但 `scripts/build-deb.sh`
在 `make package` 失败后会退化成"直接打 `.theos/_` staging"，于是照样产出一个 deb——里面是旧 dylib 或残缺内容。
装上去的现象就是"改了代码但没生效"。

修法：删掉兜底分支，`make package` 失败即整体失败；顺手把 `build-deb.sh` 从 GBK 乱码重写为 UTF-8。

### 9.4 根因三：宽度 462pt 顶满整屏

上游桌面端默认 `size=462`，手机屏宽才 393pt。加一条上限：`size = min(size, 屏宽 × 0.55)`。

### 9.5 证据

- CI run `43707503400`（commit `24c0a21`）绿；产物 `com.vboxai.littlefatlady_0.1.0-36_iphoneos-arm64.deb` 558600 B，sha256 `3e367fc14dcc68b32f00b7176493d4bc97b079dfe627a6d713222c4a28477727`。
- deb 内 `data.tar` 只剩一条素材：`var/jb/Library/Application Support/DSHPet/demo.mov`（2732076 B）；dylib 207120 B。
- `control` 的 `Name:` 字节为 `e5 b0 8f e8 82 a5 e5 a8 98`（"小肥娘" 的 UTF-8），确认中文没坏。

### 9.6 教训（已进 MEMORY）

- rootless 布局下，**任何写到 `/var/mobile` 的静态文件都必须走 postinst**，不能直接放 `layout/var/...`。
- CI 里"失败也打包"的兜底是毒药：它把编译错误变成安装后"功能没变化"，浪费一整个真机往返。
- 推送器用 `base_tree` 会保留本地已删文件（旧素材路径一直被打进包），必须显式 `sha=null` 删除。

## 10 视觉修正：宠物被大片透明边围住（0.1.0-40）

### 10.1 现象

装 0.1.0-36 后水母出来了，但看着"离上下边缘很远"——像被一圈看不见的空白包着，显得小。

### 10.2 根因

量化后很清楚：素材 540×304，水母实际只占 `bbox=[167,57,373,259]`（206×202），
**宽向填充率 38%、高向 62%**，剩下全是透明像素。宿主又按 2160:1215 的宽高比写死高度，
等于把这个"胖画布"整个摆上去，视觉上就是一堆空白。

### 10.3 修法（两条一起做，缺一条都还在）

1. **素材紧裁**：按所有帧 alpha 并集取框 `232×228 @ (154,43)`，再缩放输出 320×314，
   填充率 62% → 89%。ProRes 4444-alpha、`-qscale:v 16`，2.34MB（原来 2.73MB）。
2. **布局按真实比例**：`DSHPetPlayer` 暴露 `naturalSize`（取 `AVAssetTrack.naturalSize`），
   `DSHPetOverlay` 拿到后立刻 `petH = petW × natH/natW` 重算宿主高度。
   以后换任何素材（上游是 2160×1215，也可能是方图）都不会再留白。

### 10.4 过程中踩的坑

- `check-repo.mjs` 有 5MB 单文件上限，第一版紧裁后是 5.78MB → CI 在"仓库自检"就红了，
  不是编译问题。压到 2.34MB 过。
- 给 `DSHPetPlayer.h` 加 `naturalSize` 时我按 `- (BOOL)hasAsset;` 找锚点，但头文件里其实是
  `@property (nonatomic, readonly) BOOL hasAsset;` → 替换没命中，编译报
  `no visible @interface ... declares the selector 'naturalSize'`。改成整文件重写为 UTF-8（含正确声明）才通。

### 10.5 证据

- CI run `43712133870`（commit `324dacc`）绿；产物 `com.vboxai.littlefatlady_0.1.0-40_iphoneos-arm64.deb` 452668 B，
  sha256 `83f9ea0f511a88b00b72ae939f5eeab6aa436cebd5de3bfce88d8a31cdeb8cc0`。
- 新增日志 `pet-aspect`：`natW/natH/boxW/boxH`，真机上可核对"宿主比例 = 素材比例"。

### 10.6 待验

水母在同一次点击/拖拽下明显变大；四周无多余透明留白；旋转后仍居中不乱。

## 11 打包事故：postinst 重启 SpringBoard 把 dpkg 事务打断（0.1.0-42 修）

### 11.1 现象（真机）

装 0.1.0-40 时 Sileo 中途退出；之后一打开 Sileo 就提示"dpkg 被中断"，紧接着注销桌面。

### 11.2 根因

`layout/DEBIAN/postinst` 末尾写了：

```sh
sbreload || killall -9 SpringBoard
```

dpkg 此刻还在 configure 阶段，SpringBoard 被杀 → Sileo（跑在 SpringBoard 之上的进程树）连同安装事务一起断掉
→ 包停在 `half-configured`。之后每次打开 Sileo 都会尝试收尾、再失败、再注销。

另有一个隐患：`postrm` 无条件 `rm -rf /var/mobile/Library/DSHPet`，在 **升级** 时也会执行（dpkg 传参 `upgrade`），
等于每次升级都清掉日志与素材。

### 11.3 修法

| 文件 | 改动 |
|---|---|
| `layout/DEBIAN/postinst` | 删掉所有 respring/killall，只留 mkdir/cp/chown，全部 `|| true`；结尾打印"重启桌面后生效" |
| `layout/DEBIAN/postrm` | 仅 `remove|purge` 时删数据，`upgrade` 等参数不动 |
| `packages/ios/Makefile` | 删掉 `after-install:: install.exec "sbreload"`（deb 路径本来不执行，但会误导） |
| `docs/RECOVERY.md` | 新增：half-configured 的图形化自救步骤（Sileo 修复 / 卸载 / Filza 删 lock 与 updates） |

### 11.4 证据

- CI run `43721611769`（commit `e4784f0`）绿；产物 `com.vboxai.littlefatlady_0.1.0-42_iphoneos-arm64.deb`
  453038 B，sha256 `9a1ceca36fc93268609d2f74be1178f042cc788852aff2691478281f443fedd1`。
- deb 内 `control.tar` 的 `postinst` 已无 `sbreload`/`killall`（grep 验证 0 命中）。

### 11.5 教训（已进 MEMORY）

- 装包脚本里永远不要重启 SpringBoard：dpkg 事务会被打断，代价是用户手机半瘫。
- 维护脚本必须处理 dpkg 的 argv[1]（`configure`/`remove`/`upgrade`/`purge`），否则升级即丢数据。

## 9 尺寸与捏合（v0.1.0-46）

### 9.1 反馈

真机装 0.1.0-42 后：「最新版图标这么大」——默认 55% 屏宽（≈216pt）压住了桌面图标文字。

### 9.2 改动

| 项 | 之前 | 现在 |

| 默认宽度 | 屏宽 55% | **屏宽 30%（≈118pt）** |
| 缩放入口 | 无 | **双指捏合**，限幅 16%~62% 屏宽 |
| 落盘 | — | 松手写 `ui.json` 的 `size` 与 `sizeRatio` |
| 高度 | 按 2160:1215 写死 | 按素材 `naturalSize` 实时算（`applyPetWidth:`） |
