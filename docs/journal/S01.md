## 1 目标

不写任何宠物功能，只回答一个问题：**这个仓库能不能自动编出一个能装进这台 iOS 17.0 设备的 deb？**

验收三条：

1. deb 能被 Sileo/Filza 安装，卸载不留残渣；
2. 注入 SpringBoard 成功，且能在**没有终端**的前提下留下可读日志；
3. 二进制是 fat：`arm64` + `arm64e` 都在。

## 2 做了什么

### 2.1 工程文件（Theos，rootless 布局）

| 文件 | 作用 |
| --- | --- |
| `packages/ios/Makefile` | `TARGET=iphone:clang:latest:17.0`、`ARCHS=arm64 arm64e`、`THEOS_PACKAGE_SCHEME=rootless`、`TWEAK_NAME=DSHPet`、`DSHPet_LIBRARIES=substrate` |
| `packages/ios/Tweak.xm` | `%ctor` 打一条 boot 日志；`%hook SpringBoard applicationDidFinishLaunching:` 打一条 hook 生效日志 |
| `packages/ios/DSHPetBoot.m` / `.h` | JSONL 追加写 `/var/mobile/Library/DSHPet/logs/runtime.jsonl`；头文件用 `extern "C"` 包声明（见 §3 坑 3） |
| `packages/ios/DSHPet.plist` | filter：只注入 `com.apple.springboard`。**必须在工程根**（坑 5） |
| `packages/ios/control` | `Package: com.vboxai.littlefatlady`、`Depends: firmware (>= 17.0), preferenceloader, ellekit \| mobilesubstrate` |
| `packages/ios/layout/DEBIAN/{postinst,postrm}` | 建/删 `/var/mobile/Library/DSHPet/`；权限 755（坑 5） |
| `scripts/build-deb.sh` | 设 `THEOS`、`make clean package`、找 `packages/ios/packages/*.deb` |

### 2.2 CI（`.github/workflows/ci.yml`）

两个 job：`仓库自检`（node scripts/check-repo.mjs）+ `构建 deb（rootless · arm64+arm64e）`（macos-15：装 Theos/ldid/dpkg → 编译 → 验收 arm64e 与包结构 → 上传 artifact）。验收步会 `dpkg-deb -R` 解包、`lipo -info` 断言含 arm64e、`grep` control 字段，任一失败 job 红。

## 3 六坑与修法（全部已在 CI 里验证）

1. **`runs-on: macos-14` 在本账号不可用**：job 起跑 1 秒 `cancelled`、steps=0。探针工作流证明 `macos-15` 可跑 → 一律 `macos-15`。
2. **克隆 `theos/sdks` 冲突**：`destination path ... already exists and is not an empty directory` → 先 `rm -rf "$THEOS/sdks"` 再 clone。
3. **链接报 `Undefined symbols ... DSHPetBootLog(NSString*, NSDictionary*)`**：Logos 以 ObjC++ 编译 `.xm`，C 函数名被 mangle → 头文件用 `extern "C" {}`，`.xm` 与 `.m` 都 include。
4. **`Tweak.xm:1:1: error: unexpected character <U+FEFF>`**：PowerShell `Set-Content -Encoding UTF8` 写入 BOM → 全部源码改**无 BOM UTF-8**。
5. **`missing a filter property list. Make sure it's named "DSHPet.plist"`**：filter plist 必须在**工程根**，放 `layout/Library/MobileSubstrate/DynamicLibraries/` 不算；同时 `postinst/postrm` 必须 755，否则 dpkg 报维护脚本不可执行。
6. **产物路径**：Theos 输出在 `packages/ios/packages/*.deb`，不是 `packages/ios/*.deb` → 脚本与 CI 的 `ls`/artifact path 都要跟。

## 5 与计划的偏差 / 未做

- **真机探针改由「装机即验」代替**：操作员明确不走脚本（不会用终端），所以 S1 的真机验证＝装 deb → 看 `/var/mobile/Library/DSHPet/logs/runtime.jsonl` 是否出现 `boot` 与 `springboard-hooked`。
- **未验证项**：实际安装、注入、日志落盘、卸载清残留——全部 `NOT RUN`，等操作员装机。
- **未做 roothide 变体**：本阶段只出 rootless。Relaxin 属 roothide 体系，Sileo 在 RootHide 环境安装 rootless 包时一般会自动改写路径；若装完**没有任何日志**，先判「未注入」，下一轮补 roothide 变体（`THEOS_PACKAGE_SCHEME=roothide` + rootless 专用前缀改写）。
- 日志路径用 `/var/mobile/Library/DSHPet/`（数据目录），**不随包变体变化**，卸载脚本会清。
