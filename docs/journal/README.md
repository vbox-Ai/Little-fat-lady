# journal 目录规范

每个阶段一个文件：`S00.md`、`S01.md`……与方案 §16 的阶段号一一对应。

## 六段（缺一段即视为阶段未关闭）

```markdown
# S<xx> · <阶段名>

- 日期：YYYY-MM-DDTHH:MM+08:00
- commit：<推送后回填，本地与远端必须同串>
- 人日：计划 x / 实际 y

## 1. 做了什么
（能复述的事实，不要"完成了相关功能"这种话）

## 2. 证据
（命令 + 输出摘要 + 文件路径 + 哈希；截图放 docs/img/ 并在这里引用）

## 3. 决定
（与技术选型/取舍有关的判断，写了就进 MEMORY.md 的关键决策）

## 4. 遗留
（明确"下阶段做"还是"阻塞等操作员"）

## 5. 风险
（新出现的风险编号，同步到方案 §12）

## 6. 下一步
（唯一入口：下一阶段编号 + 第一件事）
```

## 规矩

- 不写"同上""略""见代码"——只读 journal 必须能复现当时判断。
- 证据里的哈希/路径/版本号必须是真的；没跑过的写 `NOT RUN` 并给重跑命令。
- 决定（第 3 段）如果推翻了旧决定，要写清"推翻哪条、为什么"。
