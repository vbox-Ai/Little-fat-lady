## 1. 目标

把 S3 的"整段循环播放"升级成"按状态挑片段"：待机能抽签、点一下有反馈、拖拽有专用动作、睡觉有独立池。
一句话验收：**放着不动它会自己换动作，点它会回应，拎起来会挣扎。**

## 2. 实现

| 文件 | 改动 |

## 5. 踩坑

1. 用 `str.replace("@end", ...)` 往实现段插方法，**命中的是类扩展的 `@end`** → 方法体落在 `@interface` 里，
   报 `expected ';' after method prototype` + `method definition not found`。定位靠日志行号（`DSHPetPlayer.m:16`）。
   规矩：**插入点用 `rindex("@end")`**，或用具体方法名做锚点。
2. 发布 JSON 里带中文，PowerShell here-string 会被控制台编码打坏 → 一律 python 写 UTF-8 JSON 再 `POST`。

## 8. 真机第 4 轮：「还是蓝水母」（0.1.0-53）

**现象**：装 0.1.0-52 后桌面上仍是蓝色占位水母（我手绘的 demo），不是小肥娘。

**证据**：python 解 deb 的 `data.tar`，包内同时存在

- 平铺：`idle.mov / turn.mov / click.mov / drag.mov / sleep.mov`
- 分桶：`idle/ turn/ click/ drag/ sleep/ balance/ workstatus/ whisper/ eat/ play/` 共 114 段

**根因（两条叠加）**

1. `DSHPetAnimator buildIndex` 把平铺片按**文件名前缀**归类，`idle.mov` 与 `idle/001-idle.mov` 同属 `idle` 桶 → 抽签各占一半，一半概率抽到 demo。
2. `postinst` 已改成不杀 SpringBoard，装完**没手动重启桌面**时跑的还是旧 dylib → 看起来"改了没用"。

**修法**

- `ci.yml` 铺完素材包后 `rm -f "$DEST"/*.mov`：包装里只留分桶。
- `postinst`：先铺分桶并置 `BUCKET_COPIED=1`；有真素材就不铺演示片，并 `rm -f` 掉老包装留下的平铺片。
- 发布说明里写死：**装完必须点「重启 SpringBoard」**。

**产物**：`v0.1.0-53`，72.53MB，sha256 `cfd5745baaa850e7017bf34cc6278702ef8d4ba1ced00c9586d4b1be70205b6b`，Release id `446226732`。

**待验**：重启桌面后是否为小肥娘；若否，取 `/var/mobile/Library/DSHPet/logs/anim.jsonl` 的 `index` 行看每类别索引到几段。

## 9. 真机第 5 轮：绿方块 → 素材根本没铺上（0.1.0-56）

**现象**：装 0.1.0-53 后桌面上是**绿色占位方块**（连 demo 都没了）。

**证据**（操作员回传 `anim.jsonl`，912 B）：

```json
{"groups":{},"evt":"index","dir":"/var/mobile/Library/DSHPet/assets","ver":"0.1.0-52"}
{"evt":"no-clip","dir":"/var/mobile/Library/DSHPet/assets","ver":"0.1.0-52"}
```

`groups:{}` + `no-clip` = 运行目录里**一个片段都没有**，dylib 起来了但没有素材可播。

**根因**：素材拷贝只靠 `postinst` 的 `cp`，而这条链在真机上没走通（roothide 类越狱里 `postinst` 与 SpringBoard 看到的根不同：一边是假根 `/Library/...`，一边是 `/var/jb/...`；`cp` 静默失败，`|| true` 把错误吞了）。

**修法**：把"找素材"从安装期挪到运行期。

- 新增 `packages/ios/DSHPetAssets.{h,m}`：`DSHPetAssetRoots()` 返回候选根，顺序
  `/var/mobile/Library/DSHPet/assets` → `/var/jb/Library/Application Support/DSHPet` → `/Library/Application Support/DSHPet` → `/var/jb/var/mobile/Library/DSHPet/assets`。
- `DSHPetPlayer findByFirstMovie`：逐个根找，命中记 `{"mod":"player","evt":"asset-root","dir":...}`。
- `DSHPetAnimator buildIndex`：同样逐根扫，命中第一个有料的根就停（避免两套素材混抽），索引改存**绝对路径**；`play:` 遇到绝对路径不再拼 `self.dir`。
- `Makefile` 加 `DSHPetAssets.m`。

**踩坑**：`buildIndex` 里 `NSFileManager *fm` 移位后变成未使用 → CI `-Wunused-variable` 报错（这套工程 warning 即 error）。另：推送脚本原先把 `layout/.../DSHPet/*.mov`（90MB）也当普通文件上传，blob 接口直接崩，改为跳过该前缀与 >5MB 文件。

**产物**：`v0.1.0-56`，72.53MB，sha256 `ab7965eee2372a65a0d1e502d59a204e92f32efd331ef612ed2ca61221f0b245`，Release id `446423334`。

**待验**：重启桌面后是否为小肥娘；若仍是方块，看 `anim.jsonl` 的 `index` 行 `groups` 是否非空、`player.jsonl` 的 `asset-root` 命中哪一路。
