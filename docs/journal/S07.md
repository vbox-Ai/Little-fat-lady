## 1. 做了什么

**面板本体（plist-only，无二进制，不新增编译目标）**
- `packages/ios/layout/Library/PreferenceBundles/DSHPetPrefs.bundle/Info.plist`：`CFBundleIdentifier = com.vboxai.littlefatlady.prefs`，`CFBundlePackageType = BNDL`。
- `…/DSHPetPrefs.bundle/Root.plist`：四组 specifier，全中文。
  - 宠物：`petEnabled`（总开关）、`edgePreset`（贴边间距 贴紧/标准/宽松）。
  - 物理与触感：`gravityEnabled`、`tiltGravityEnabled`、`hapticEnabled`、`hapticLevel`（轻/标准/重）。
  - 会话气泡：`bubbleEnabled`、`bubbleStatusEnabled`、`bridgeEnabled`、`bridgeBase`（可编辑 URL）。
  - 关于：`installedVersion`（运行期盖章，不是写死的）、仓库地址。
- `packages/ios/layout/Library/PreferenceLoader/Preferences/DSHPetPrefs.plist`：入口「设置 → 越狱插件 → 小肥娘」。

**数据面 `DSHPetPrefs.h/.m`**
- 读三个来源，优先级从高到低：`com.vboxai.littlefatlady.prefs`（面板域）→ `com.vboxai.littlefatlady` → 落盘兜底 `/var/mobile/Library/Preferences/com.vboxai.littlefatlady.prefs.plist`（按 mtime 缓存，不常驻定时器）。
- `applyToUIConfig:` 只覆盖**用户可调项**，绝不碰 `centerX/centerY/taps/sizeRatio/sizeManual/windowLevel` 这类运行时状态；`hasKey:` 保证了「面板没设置的键不写默认值」，老用户升级不会被悄悄改配置。
- `stampVersion:` 在 SpringBoard 启动时把 `DSHPET_VERSION_STRING` 写进面板域，面板「关于 → 版本」永远等于实际装的版本。

**接线**
- `DSHPetOverlay.attachToScene:` → 读 `ui.json` → 合并面板值 → 变化则落盘 → 盖章版本。
- `applyPrefsNow`：SpringBoard 收到 `UIApplicationDidBecomeActive`（用户从「设置」退回来）时重读面板，重设触感开关/档位、宠物显隐、桥接启停、并按新间距档立即重夹一次位置。**改完不用 respring。**
- `clampedCenter:inSize:` 改成三档：贴紧 = `max(8, safeArea+4)`、标准 = `max(20, safeArea+8)`（**与面板上线前的老值逐字一致**）、宽松 = `max(40, safeArea+24)`。
- `physGravity` 增加 `physics.gravityEnabled` 判断，关掉直接返回 0。

## 3. 决定

- **面板做成 plist-only**，不为它加一个 `bundle.mk` 编译目标：CI 上多一个 bundle target 就多一类链接失败面，而当前所有需求（开关、三档选择、文本输入）plist-only 全支持。
- **不做 Darwin 热通知**：plist-only 面板发不出通知；改用 `UIApplicationDidBecomeActive`（SpringBoard 视角，用户从设置退回桌面必触发），零常驻成本。
- 面板域与运行时 `ui.json` **分开存**：面板域记「用户意愿」，`ui.json` 记「当前状态 + 合并结果」。这样即使有人手动改 `ui.json`，面板一按就回正；反过来面板没动过的项也不会被覆盖。
- 贴边间距用「三档」而不是连续滑块：`clampedCenter` 的上下界依赖 `safeArea`，自由数值容易把宠物推进灵动岛或 home 条。

## 4. 遗留

- 「检查更新」和「重置三档（全部/外观/位置）」未做（方案 §S7 行要求），进 S7b。

## 5. 风险

- **R32（新）**：plist-only bundle 若在 Relaxin/roothide 的 PreferenceLoader 2.2.8 上不认（entry 无 `detail` 键的解析差异），设置里点进去可能是空页。判定方法：点进去看有没有四组标题。若空 → 改 `detail = PSListController` + `isController = 1`，再不认就加 `bundle.mk` 编译一个 `PSListController` 子类。
- **R33（新）**：`CFPreferences` 在 SpringBoard 进程里可能读到缓存旧值；已加落盘兜底，但兜底读的是 `/var/mobile/...`，rootless 下若面板实际写到 `/var/jb/var/mobile/...` 需要补一条路径（当前未验证）。

## 6. 下一步（唯一入口）

真机装包后按顺序验：

1. 设置 → 越狱插件 → 小肥娘，四组标题都在（验 R32）；

## 9. S7b 尺寸滑块（2026-11-18）

面板加了第三组「尺寸」，`PSSliderSpecifier` / key `sizePct` / 默认 0.30 / 范围 0.16–0.62。
滑块值是**占屏宽比例**，和 `ui.json` 的 `sizeRatio` 同一量纲，不做像素换算，换机型也不会失配。

三处配套改动：

1. `DSHPetPrefs applyToUIConfig:` 增 `sizePct` 分支：夹到 0.16–0.62，写 `sizeRatio`，并强制 `sizeManual = YES`。
   这是唯一破例允许覆盖「运行时态」的键——滑块是用户明确表态，不置 `sizeManual` 就会被自动 1:1 逻辑立刻改回去。
2. `DSHPetOverlay applySizeFromConfig`：按新比例重算宽，高度**跟随素材真实比例**（`naturalSize`，拿不到时退化 2160x1215），
   再同步 `setDisplaySize:`、按新尺寸重新 `clampedCenter:` 夹一次位置（变大后不夹会顶出屏幕）。
3. `applyPrefsNow` 的回填规则：`centerX/centerY/taps/windowLevel` 一律用内存值；`sizeRatio/sizeManual`
   只在面板**没有** `sizePct` 时才用内存值回填。宽变化 > 0.5pt 走 `applySizeFromConfig`，否则走 `relayoutAndSettle:`。

## 10. R34 重置按钮做不了（plist-only 的边界）

`PSButtonCell` 要执行回调就必须有 PreferenceBundle 的可执行文件，当前面板是纯 plist，
所以「一键重置」不在 S7b 范围内。三条退路：

| 退路 | 代价 | 评价 |
|---|---|---|
| 面板加「恢复默认」开关，SpringBoard 读到就把可调项写回默认并自动关掉这个开关 | 0 依赖，纯 plist 可做 | **推荐**，S7c 做 |
| 编 PreferenceBundle 二进制（Makefile 加 BUNDLE 目标） | 多一个产物 + 签名/架构匹配风险 | 需要真正的按钮回调时才上 |
| 让用户删 `ui.json` | 用户要会进 Filza | 只写进 FAQ |
