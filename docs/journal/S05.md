## 1 目标

桌宠不再是"贴在那儿的一张图"：能被拎起来、甩出去、落地弹、侧着手机滑下去。

## 2 实现

- `onPan:` 采样位移/时间得松手速度，>250pt/s 才抛，上限 2400。
- `startPhysicsWithVelocity:` 起 `CADisplayLink`，`stepPhysics:` 用 1/120s 子步积分（重力 / 弹性 / 四边反弹 / 落地摩擦 2.5）。
- 静止判据 `|vy| < 140 && |vx| < 12`，停下即 `clampAndPersist`（省电，不空转）。
- 倾斜重力：`CoreMotion` 30Hz 采样，`physics.tiltGravity` 默认开；`|a| > 0.08` 才认，避免桌面平放抖动。

## 3 这版修的两个真机问题

1. **注销后拉长**：宿主尺寸变了、图层矩形没重算 → 新增 `refreshLayout`，改尺寸后立刻按当前帧重排。
2. **偶发发虚**：`contentsScale` 固定屏幕 scale，图层点宽不是图像宽整数分之一时每帧重采样 → 首帧按 `naturalSize.width / scale` 定宽（1:1），捏合按 1/3 pt 取整。

## 4 证据

- 素材包 `pack-upstream-0.4.9-390`（114 段 95.5MB）。

## 5 踩坑

- `_curFrame` 必须保留强引用，否则 `refreshLayout` 拿到已释放的 CGImage。
- `applyPetWidth:` 里 `round(w*ratio)` 只对齐宽度不对齐高度 → 高度落在半像素上，依旧发虚。

## 9 追加：0.1.0-102（注销后拉长 / 回缩的真正根因）

- 100 版只补了「铺满后重 fit」一条路径，没修两件根本问题：

  2. `contentsGravity = Resize` 语义就是"填满、可变形" → 任何一帧矩形没算对就当场拉伸。

## 10 追加：0.1.0-104（待机偶发糊）

- 证据：真机 `render.jsonl` 的 `pet-aspect` 全是 `natW:320,natH:314,boxW:149.67` —— 320×314 是 0.1.0-31 的演示片（方形画布），不是小肥娘素材（390×219）。
- 成因：0.1.0-53 起删除 postinst，老安装留下的平铺文件没人清；选片优先级又把平铺排在分桶前，`idle` 类别里两者混播 → 抽到 320px 那段放大 1.4× 就糊一次。
- 修法：`DSHPetAnimator` 建索引前探测分桶，存在则完全忽略同级平铺文件；`DSHPetPlayer` 选片改「分桶(idle 优先) > 顶层 main.* > 其它平铺」；`_naturalSize` 改每帧同步。
- 产物 `v0.1.0-104`：95.58MB，sha256 `842628de422d6f2550c1071f36000b8462f22fd5d2cf1c7382c3fba781ee60ca`，Release `448405146`。

## 11 追加：素材升到 512px + S5 震动（0.1.0-112 起）

- 用户复测 111：「站立疲惫左右晃必糊」「向左跑必糊」「向左张望偶尔」。1:1 像素已经修对，问题在素材本身。
- 实测（决定性的三条）：
  - 上游源片是 **640x360 / 24fps**（抽样 3 段一致），我们转码时先缩到 390 → 白扔 40% 像素。
  - 画布里角色只占 **129–192px 宽**（390 画布两侧大量透明），显示 130pt 时角色就是 135px —— 一点余量都没有。
  - 512 帧 × 121 帧超过原 `cap=120` 的预解码上限 → 循环少一帧，且超长片段后半段可能回落低清代理。
- 修法：
  1. 素材包重出 **512x288 / 12fps / q50**，从 640 原生只缩一次（Release `pack-upstream-0.4.9-512`，137.5MB，114 段，alpha extrema 0–255 验证过）。
  2. `layoutContentsForImage:` 改「铺满宠物框，但不超过 1:1」：框小→缩小采样（CA 降采样锐），框大→夹住，永久禁止放大。
  3. 预解码上限 120 → 256，并新增 `webp-truncated` 警告日志 + `webp-ok.decoded/mb` 观测。
- S5 震动落地：新增 `DSHPetHaptics.h/.m`，事件表 = 点击轻 / 拖拽轻 / 抛出轻 / 撞边(>300pt/s)重 / 落地中；配置 `physics.hapticEnabled`（默认开）、`physics.hapticLevel`（light·normal·heavy）；低电量或系统关触感自动跳过。
- 待验：左右晃 / 向左跑是否不糊；撞边有没有「重」感；`webp-ok` 里 `decoded` 应等于 `frames`。

## 13 追加：发虚结案 + 换动作卡顿（0.1.0-115 起）

- 操作员在 Filza 里删掉 `/var/mobile/Library/DSHPet/assets/color/` 与 `matte/` 后复测：**"确定不糊了"** —— 发虚根因正式确认。
- 根因（读码 + 实测双向确认）：`DSHPetAnimator.m` 建索引时给 color 根无条件 `+100000` 分、`DSHPetAssets.m` 见到 `color/` 目录就直接 return 不清，于是双路时代残留的 `color/*.mp4`（320×180）永远压过新 webp，抽片恒定走 320 素材 + 合成链路 → 轻微但必然的糊。只在 idle/move 复现，因为残留只在那两个桶。
- 结案动作（本轮代码）：选片打分改成「webp 绝对优先」，播放层拒绝非 webp，启动时自清 color/matte。**不再依赖用户手动删目录。**

### 卡顿（删目录后被暴露出来的第二个问题）

- 现象：换动作（点击/拖拽/扔）卡住几百 ms 到 1s+。
- 根因：`DSHPetPlayer.m` 的 `playWebPAtURL:` 把 **121 帧整段预解码跑在主线程**（`kCGImageSourceShouldCacheImmediately`），512 素材每帧约 590KB ≈ 71MB 软解量。之前一直播 320 mp4 走 AVPlayer 硬解，所以没暴露；一旦真的开始播 512 webp（CPU 软解）立刻现形。
- 修法（commit `8c73a8e5` 首次尝试 → 本轮补 `__bridge` 修正）：
  1. 主线程只做：开文件、读帧时长属性、解**第 0 帧**立即上屏（消除换片空白）；
  2. 剩下 120 帧的循环 `dispatch_async` 到 `QOS_CLASS_USER_INITIATED` 后台队列；
  3. 回主线程前比对 `_webpToken`（每次换片自增），对不上直接 `CFRelease(src)` 丢弃 → 快速连点不会互相覆盖，也不会 use-after-free；
  4. 第 0 帧用 `CFBridgingRelease` 交给 ARC（`_curFrame` 要活到下一次 `refreshLayout`，裸 `__bridge` + `CGImageRelease` 会留悬空指针）。
- 观测点：`player/webp-ok` 的 `decoded == frames`、`player/webp-truncated` 应为 0 条。
- 待验（**NOT RUN**）：真机点击/拖拽是否不再卡；快速连点 5 次是否出现旧片盖新片。
