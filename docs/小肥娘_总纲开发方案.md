> **关键结论（修正版，2026-11-18）**：
> - S0–S7 做完的只是**「壳」**：注入、窗口、渲染、**原地动作动画**、**被动物理**、多开、只读气泡、5 组面板。**没有任何「内容能力」落地**。
> - 「行走」「读屏」「自动下单」「音乐律动」「服装」这五样，**dsh-pet 上游本身都没有**，是之前视频里「超级插件/PetDFY」那套产品的能力。要移植到本项目 = **新增功能模块**，不是改已有阶段，需要单独立项。
> - 其中「自主行走」是最大缺口：S4 的 `move` 只是**动画文件名分桶前缀**（迈步动作的贴图），S5 的 `center` 赋值全是**拖拽/甩出/旋转重排**，代码里没有任何 `wander/moveTo/目标点` 逻辑——宠物现在**只会原地做动作，不会自己移动**。

### S3 · 单宠物渲染 ✅（已关闭，v0.1.0-46）

- **目标**：宠物本体上屏（透明无黑底），冷启 <1.5s。
- **详细步骤**：① AVPlayerLayer 池（预载 3）；② 首帧预热 + 静态帧垫底；③ 统一走 WebP 合成 + 亮度键。
- **踩坑 3 根因**：rootless 前缀把素材装错位置（应放 Library/Application Support 由 postinst 拷）；CI dpkg-deb 兜底掩盖编译失败（删兜底）；宽度顶满屏（加 min 上限 30%）。
- **关键参数**：默认 30% 屏宽 + 双指捏合 16%–62% + sizeRatio/sizeManual 落盘；亮度键 CIColorMatrix(RGB=1,A=luma)+CIBlendWithMask。

### S4 · 动画链与状态机 ✅（已关闭，v0.1.0-50 起）

- **目标**：分桶动画 + 无缝衔接 + **原地动作抽签（⚠️ 无行走，宠物不移动位置）**。
- **明确边界**：`move` 桶是**「迈步」动作的贴图动画**（原地播放），不是移动窗口。本阶段 + S5 都没有实现「宠物自主走到某位置」——那是未做的「自主行走」能力。
- **详细步骤**：① 按文件名前缀分桶 idle/turn/move/click/drag/sleep；② 6–14s NSTimer 抽签（70% idle / 30% turn）；③ tap 在 click 轮播，drag 切 drag→idle；④ playClipAtURL 只换 AVPlayerItem 不重建 layer。
- **踩坑**：短剧全屏压住宠物（windowLevel 1100→1500）+ AVPlayer 中断（ambient+mixWithOthers+恢复+3s 看门狗）；素材平铺片 vs 分桶混抽 → 只留分桶；黑底 → 统一合成+亮度键；蓝方块（首帧通知时序）→ 观察者先注册。
- **参考**：dafeiyu-pet 行走状态机（移植清单 `dafeiyu-pet_行走状态机与拖拽_移植清单.md`）。

### S5 · 物理与交互 ✅（已关闭，v0.1.0-97→115）

- **目标**：拖拽 / 甩抛 / 互撞 / 挤压，与桌面版手感一致，系统手势零冲突。
- **详细步骤**：① onPan 采样速度 >250pt/s 抛掷（上限 2400）；② CADisplayLink 1/120s 子步积分（重力/弹性/四边反弹/摩擦 2.5）；③ 静止判据 |vy|<140&&|vx|<12 停表省电；④ CoreMotion 30Hz 倾斜重力（|a|>0.08 才认）；⑤ 震动 DSHPetHaptics 三档。
- **踩坑**：发虚=残留 color/*.mp4 压过新 webp → 选片 webp 绝对优先 + 启动自清；换动作卡顿=121 帧整段预解码在主线程 → 主线程只解第 0 帧 + 后台队列 + _webpToken 防竞态。
- **参考**：dafeiyu-pet 拖拽三件套（drag_offset=鼠标-窗口左上角，抓哪点贴哪点）；Shijima-Qt Environment/Mascot。

### S6 · 多开与 UI 层 ✅（基本关闭，v0.1.0-123→136）

- **目标**：多实例（≤8）+ 气泡 + 长按菜单 + 待办面板 + 表情包。
- **详细步骤**：
  - **S6a 气泡**：DSHPetBubble（深色圆角，宽上限 min(宿主宽×0.74,330pt)，头顶 8pt 自动翻下，点击收起，6.5s 淡出）。状态机：IDLE→CLEAN→SHOW→FADE→IDLE（§21.5）。
  - **S6b 桥接**：DSHPetBridge（NSURLSession 轮询 `/state?since=counter` 2.5s，notify.counter 去重；文本清洗 DSHPetCleanBubbleText：去角色前缀 `^[^：:\n]{1,8}[：:]`、去 Markdown、代码块→［代码］、链接留文字、3 行截断超 240 字；只读红线不调 /quit 不写 /config 不碰 /ws/mobile）。

  - **S6d 长按菜单**：DSHPetMenuPanel 自绘深色圆角 + 取消红；**修 hitTest 放行（touchRoots 注册交互视图）**。**表情包只做了轮播，无挑选界面（未完成）**。

### S8 · 日志与诊断 ⬜（4 人日，详细步骤）

**目标**：不连电脑，手机上说清「哪一步/哪个模块/什么错/崩溃前在干什么」，证据能导出。

1. **四类日志**（§8.1）：A 运行 `logs/runtime-YYYYMMDD.log`（生命周期/模块事件/性能采样，Info）；B 调用 `logs/calls-YYYYMMDD.log`（每个功能入口：谁触发/参数摘要/耗时/成败，全开）；C 错误 `logs/errors-YYYYMMDD.log`（可恢复错误+错误码）；D 崩溃 `crash/*.json + *.ips`。
2. **JSONL 行格式**（§8.2）：字段 `ts lvl mod evt sid pid dur_ms ok err err_code kv stack ctx`；模块枚举 inject/render/physics/bubble/voice/ai/net/assets/config/prefs/sleep/hud/crash；错误码前缀 E_CFG_/E_ASSET_/E_NET_/E_AI_/E_DEC_/E_PERM_/E_INT_。
3. **保留策略**：面板组 12 提供保留 1/2/3 天（默认 1 天）；单文件 2MB 轮转；每日 25MB 上限；到顶先丢最旧再丢 debug；同模块同 evt 1s 去重只记首次+计数；写盘走串行 Utility 队列，主线程只入环形缓冲。
4. **崩溃三腿**（§8.3）：① 钩子 `NSSetUncaughtExceptionHandler`+signal 裸写 256 条环形缓冲（只用 async-signal-safe，不 malloc/NSString/NSLog）再 re-raise；② 心跳 session.json 每 5s（未闭合会话=OOM/watchdog）；③ 系统报告扫 CrashReporter 匹配 SpringBoard 解析栈顶 8 帧。
5. **脱敏**（§8.4）：Token/apiKey/Cookie → sk-\*\*\*；URL 去 query；诊断包生成前展示清单。
6. **面板日志页**（§8.5）：级别/模块过滤 + 实时日志 + 崩溃列表 + 三种导出（导出日志 jsonl/txt、生成诊断包 zip=logs+crash+脱敏配置+env.json+session.json、复制最近 500 行）。

**验收（6 条）**：实时日志延迟 <1s；`kill -SEGV` 打崩 SpringBoard 后崩溃列表 +1 带栈顶；断网下载 E_NET_\* 入 errors 面板黄条；改保留天数旧文件不立刻删；导出 jsonl `jq` 可解析无密钥；8h 长跑日志 ≤上限 FPS ≥95%。

### S9 · 素材下载器 ⬜（4 人日，详细步骤）

**目标**：分层素材 + 多节点 + 断点续传 + 校验 + 清理。

1. **分层**（§9.1）：L0 占位（待机/移动/点击 3 段 480p HEVC-alpha，<8MB 随 deb）；L1 完整包（上游 1080p + 表情包 27 张 + 字体 ≈100MB，设置里下载，提供 720p/480p 可选）；L2 自定义（用户自带 .mov/.webm）。

**验收**：弱网断点续传成功；校验失败可重下；占用统计准。

## 十、第四轮遗漏补齐（读核心 .m 实现源码对账，2026-11-18）

> 把 13 个 `.m` 源码文件拉到本地逐个读（Boot/Overlay/Animator/Player/Assets/Bubble/Bridge/Haptics/Prefs/Pet/Crew/TodoPanel/MenuPanel），以下是从**实现代码和注释里的真机教训**挖出的、前三轮没覆盖的硬细节。这些是"照着写不会踩"的关键。

### 10.1 日志层序列化安全（DSHPetBoot.m —— 最高优先，能直接崩 SpringBoard）

- 日志是 JSONL（一行一条，按 mod 分文件，目录 `/var/mobile/Library/DSHPet/logs`）。
- **`DSHPetJSONSafe` 是保命函数**：`NSJSONSerialization` 遇到 **NaN/Inf 或 CGSize 之类的 NSValue 会抛 NSInvalidArgumentException**，而这个异常在 SpringBoard 里没人接 → `abort()` → 安全模式。所以所有值先转 JSON-safe（NaN/Inf 转 `"NaN"` 字符串、NSValue 转 `description`、深度 >4 转字符串）。
- 序列化再失败也不许抛：写一条最简 fallback 记录。
- **目录由代码自己建**（`createDirectoryAtPath`）：roothide 的 dpkg 有时执行不了维护脚本，不能依赖 postinst 建目录。

### 10.2 启动残留清理的教训（DSHPetBoot.m）

- 只清"确定是老东西"的那几样：`color/`、`matte/` 两目录（双路合成时代 320×180 mp4）+ 根级散放 `.mp4/.mov/.m4v` + 6 个演示片名（idle/turn/click/drag/sleep/demo.mov）。
- **血泪教训**：上一版写的是"不是 color/matte/main.* 就删"，等于每写一条日志就把新素材的 idle/move 分桶全删一遍——**谁的分桶被删，谁就绿方块**（发虚问题的老根就在这）。

### 10.3 偏好域三级读取 + 读盘兜底（DSHPetPrefs.m）

- 三级优先级：bundle 域 `com.vboxai.littlefatlady.prefs` → 主域 `com.vboxai.littlefatlady`（早期脚本兼容）→ **直接读盘兜底** `/var/mobile/Library/Preferences/com.vboxai.littlefatlady.prefs.plist`。
- **roothide/rootless 下 CFPreferences 偶尔拿不到**（守护进程缓存旧域）→ 必须读盘兜底，否则配置改了不生效。
- **配置键映射表**（面板键 → 内部 cfg 键，开发必须对照，含两处键名变换）：
  - `tiltGravityEnabled` → 内部 `physics.tiltGravity`（**键名变了**）
  - `hapticEnabled/hapticLevel` → `physics.hapticEnabled/hapticLevel`
  - `gravityEnabled` → `physics.gravityEnabled`
  - `sizePct` → `sizeRatio`（0.16–0.62 夹紧）**+ 强制 `sizeManual=YES`**（否则自动 1:1 逻辑会把滑块值改回去）
  - `edgePreset` → `edgePreset`（0/1/2 夹紧）
  - `bridgeBase` → `bridgeBase`；`bridgeInterval`（内部键，2.5 默认 1–10 夹紧，面板暂无此键）
  - `petEnabled/bubbleEnabled/bubbleStatusEnabled/bridgeEnabled/multiPetsEnabled/perSession/multiPetsMax` 各自直映
- `stampVersion` 写 `installedVersion` 键；私有方法必须先声明（`-Werror` 会红）。

### 10.4 窗口层"彻底透明"四要素（DSHPetOverlay.m）

浮层必须"彻底透明"，下面任何一项留着都会露馅：**不透明标记（isOpaque）、组透明度（groupOpacity）、光栅化（shouldRasterize）、默认阴影**。此外图层要**对齐到整数设备像素（1/3 pt）**，否则落在半像素上 CA 会插值 → 发虚。

### 10.5 尺寸判据的根因 bug（DSHPetOverlay.m）

- **不能拿"小于某个绝对值"当"没配过"的判据**：用户捏到 118pt 是合法值，上一版写 `size < 120 → 300` 正是"缩小后注销又变大"的根因。
- 尺寸例外规则：面板滑块一旦存在就是用户明确表态，**必须让它赢**（配合 10.3 的 sizeManual=YES）。

### 10.6 手势不能互相 require（DSHPetOverlay.m）

两个手势各管一段，**不要**加 `requireGestureRecognizerToFail`：给 pan 加"必须等长按失败"会让拖宠物先卡 0.45 秒，手感直接废掉。

### 10.7 素材分辨率硬约束（DSHPetAnimator.m / DSHPetPlayer.m）

- **320px 素材塞进 130pt(=390px) 宿主会被放大 1.22–1.4 倍** → 真机"待机时偶尔糊一下/某些动作一直发虚"。
- 结论：素材分辨率必须 ≥ 宿主 pt × scale，否则抽到低清段就发虚；`color/*.mp4` 残留会**永久夺走选片权**。
- 播放器判据必须是"找到可用素材"，不能是"图层是否已建出来"；frame 铺满宿主后必须按图像比例重新 fit；`_curFrame` 必须让 ARC 接管所有权。

### 10.8 roothide 假根随机命名（DSHPetAssets.m）

roothide 的真实越狱根是**随机命名的假根**（`.jbroot-XXXXXXXX`），未链接 libroot 的 dylib 无法把 `/var/jb` 重定向过去 → 必须自己去容器目录里找，不能写死 `/var/jb`。

### 10.9 触感与菜单细节（DSHPetHaptics.m / DSHPetMenuPanel.m）

- 触感：三个 `UIImpactFeedbackGenerator`（light/medium/heavy）+ `_shift`（-1/0/+1 档位）夹到 0–2；**低电量模式不震**（省电优先，也让"没反应"有解释）；`minInterval` 防抖。
- 长按菜单：自绘深色圆角面板（bg 0.11 alpha 0.97），**最后一行固定"取消"（红色）**；优先摆宠物上方，放不下翻下方，左右夹安全区。

### 11.2 排序逻辑（为什么这个顺序）

1. **P0 清阻塞**：闪退是硬伤必须最先；面板 5 组补到 15 组是"能力可见"的前提（不然做完功能用户也调不了）；表情包/重力开关是遗留小尾巴。
2. **P1 打地基**：日志（崩溃能查）+ 素材下载（素材能换）是后面所有能力的前提。
3. **P2 S10 内容能力**：按依赖链——桥接（8）是唯一入口 → 对话（9）→ 碎碎念（10）/梦话（11）依赖对话通道 → 语音（12/13）→ 余额/待办/天气/工作状态/睡觉（14–18，全靠桥接拉数据）→ 通知/字体语言/pet pack（19–21 收尾增强）。
4. **P3 S10a 自主行走 + 动作库**：这是用户点名的"不能行走"硬伤，且**上游本来就有 moves 系统**（见下 11.4），补做即可；动作库 80 段是"只会简单动作"的根因——移植版只接了 idle/turn/click/drag/sleep 五桶。
5. **P4 四样新模块**：按复杂度——音乐律动（有清单，2）→ 读屏（2）→ 自动操作（依赖读屏，3）→ 服装（依赖素材，2）。
6. **P5 收口**：全部能力齐了再打磨 + 发布。

### 11.3 每项关键实现要点

- **碎碎念唠叨（10）**：`whisperEnabled:true` + `eventsRefreshSec.whisper=300`（5 分钟一次）+ `events.whisper` 3 段动画（擦桌/发呆/对屏碎碎念）。手机端：`GET /state` 拿 whisper 事件 → 气泡显示 + 挑对应动画段。**这跟"AI 对话"是两回事**：对话是用户发起有来有回，碎碎念是宠物**自己定时唠叨**——之前一直被我混在一起，导致漏列。
- **梦话（11）**：`eventsRefreshSec.sleepTalk=60`，睡觉状态下每分钟可能说一句，台词取 `sleepStartTexts/sleepEndTexts/sleepRefuseTexts` 三类。
- **语音 TTS 可插拔 Provider（12）**：**已定方案 = 做接口，不只做豆包**（用户 2026-11-18 拍板，方便后期适配）。完整协议、配置键、三条引擎实现、降级链、面板 UI、验收标准见 **§11.7**。一句话：`DSHPetTTSService` 统一入口 + `DSHPetTTSProvider` 协议 + registry 枚举，新增引擎只改 4 步、**核心零改动**。
- **移动系统（22，最关键）**：上游 `animations.moves.default{minDist:60,maxDist:240,margin:20,leadSec:2,tailSec:2}` + `moves.actions` 3 段 + `animationWeights.move:5`。逻辑 = 定时器抽签决定"要不要走" → 随机目标距离（60–240px，留 20px 边距）→ 播 `leadSec` 前导动画（2s）→ 播放走路动画（可循环）→ 到达后播 `tailSec` 收尾（2s）→ 回 idle。**移植时照抄这六个参数，不要自己发明**。
- **自主漫游（23）**：在 22 基础上加 dafeiyu-pet 的三模式（wander/follow/still）+ 朝向四态 + `SPEED=380 px/s` + `ARRIVE_DIST=12` + 到达后休息 8–18s。参考 `dafeiyu-pet_行走状态机与拖拽_移植清单.md`。
- **动作库（24）**：`animations.categories` 五个分类共 **80 段**（小动作18/玩耍27/吃什么12/时节21/文字2），每类有权重（20/20/16/14），`文字`类有 `noMirror:true` 不可镜像。移植 = 索引器按分类建桶 + 权重抽签 + noMirror 时禁用 facing 镜像。
- **口型（26）**：说话时按音频/文本节奏切换嘴部帧（PetDFY 的 `feat.eyes` 有类似分层；dsh-pet 是独立口型帧）。
- **通知播报（19）**：`notificationsEnabled` + `notifyWhenFocused` + `voiceNotify`，配合 §15.4 的 UNUserNotificationCenter。
- **字体 + 8 语言（20）**：`font{family:"candy",size:21,followPet:true}` 对应上游 `上首软糖体.ttf`；语言 8 种回退顺序。
- **pet pack（21）**：换整套宠物（不同素材包 + 独立动画池），与"服装切换"区别——pack 是换角色，服装是同一角色换衣服。
- **音乐律动（29）**：移植 `音乐律动_节拍检测与动作状态机_移植清单.md`（短时能量 onset → 律动状态机 → 6 动作 sway/bob/wave/hold/nod/shake + LRC 逐词歌词浮层）。
- **读屏（30）**：截图 → base64 → 视觉模型（OpenAI 兼容）→ 气泡+语音。依赖 9 的自定义模型通道。
- **自动操作（31）**：读屏 + 越狱模拟触摸（参考 WVNoJump/Duo 注入手法），实现"打开美团→搜索→下单→停在支付前"。**支付红线：绝不代输密码，交还控制权**（沿用视频里那句"密码我不敢碰，爸爸自己按还是告诉我？"）。
- **服装（32）**：多套 webp 素材包 + 面板选择器 + 切素材根目录。

#### 11.7.2 Provider 协议（照抄就能加新引擎）

```objc
// DSHPetTTSProvider.h
@protocol DSHPetTTSProvider <NSObject>
@required
+ (NSString *)providerID;            // "doubao" / "edge" / "native" / "minimax"...
+ (NSString *)displayName;           // 面板显示名（中文）
+ (BOOL)isAvailable;                 // Key 已配 / SDK 在 / 宿主可达
/** 能力协商：@{@"pitch":@YES,@"speed":@YES,@"style":@YES,@"volume":@YES,@"stream":@NO} */
+ (NSDictionary<NSString *, NSNumber *> *)capabilities;
/** 音色目录（三种来源：内置数组 / 远端拉取 / 用户手填 ID） */
+ (void)discoverVoices:(void (^)(NSArray<DSHPetVoice *> *voices, NSError *err))done;
/** 合成。返回 audioData=nil 且 didSpeakInline=YES 表示引擎自己播（如 AVSpeechSynthesizer） */
- (void)synthesize:(DSHPetTTSRequest *)req
        completion:(void (^)(DSHPetTTSResult *res, NSError *err))done;
- (void)cancel;
@end

@interface DSHPetTTSRequest : NSObject
@property (nonatomic, copy)   NSString *text;
@property (nonatomic, copy)   NSString *voiceId;   // nil → 引擎默认音色
@property (nonatomic, copy)   NSString *style;     // 说话风格（不支持的引擎忽略）
@property (nonatomic, assign) double pitch;        // -12…+12（半音）
@property (nonatomic, assign) double speed;        // 0.5…2.0
@property (nonatomic, assign) double volume;       // 0…1
@property (nonatomic, copy)   NSString *format;    // @"mp3" / @"wav"
@end

@interface DSHPetTTSResult : NSObject
@property (nonatomic, strong) NSData *audioData;   // nil = 引擎自播
@property (nonatomic, assign) BOOL didSpeakInline;
@property (nonatomic, copy)   NSString *mimeType;
@end
```

#### 11.7.4 引擎实现要点（三条，各自的坑不同）

| 引擎 | 实现 | 关键坑 |
|---|---|---|
| **Doubao（豆包语音）** | HTTP 直连火山引擎 TTS：`POST /api/v1/tts` 带 `appid/token/cluster/voice_type/encoding/speed_ratio/pitch_ratio/text`；返回 base64 音频或二进制流 | ① 音色必须用**已开通的 2.0 音色**，否则 403；② `pitch_ratio` 是倍率不是半音，面板的 +3 要换算；③ Token 是短期凭证，需支持「填长期 Key」或「填 token」两种模式；④ 失败必须降级到 native，**不许静默** |
| **Edge（DSH 宿主）** | `POST {base}/dsh-pet-7340/voice/speak {text,voice,rate}` → 音频流；音色目录 `GET /voice/voices` | ① 目录来自宿主，**不许硬编码音色名**；② 选中的引擎被卸载后必须报 `E_VOICE_PROVIDER_GONE`，不自动换；③ 走 42429 隧道时超时设 3s，超过就降级 |
| **Native（原生音效）** | `AVSpeechSynthesizer` + `AVSpeechUtterance`，`didSpeakInline = YES` | ① 必须在主线程创建 synthesizer；② `pitchMultiplier` 范围 0.5–2.0（不是半音）；③ 来电/其他音频打断时要 `continueSpeaking` 或重播；④ 兜底引擎**不可关**（面板置灰 + 说明"保底引擎，必开"） |

#### 11.7.5 降级链与调度（写死逻辑，别每次重想）

```
speak(text)
 ├ 1. 若 quietHours 命中 → 静默 + 写 voice.tts.skip reason=quiet  （不报错）
 ├ 2. 缓存命中（key = sha256(text|provider|voice|pitch|speed)）→ 直接播放，跳 4
 ├ 3. 按 providerOrder 过滤出 (enabled && isAvailable) 的列表
 │     for p in list:
 │         res = p.synthesize(req, timeout=3000ms)
 │         ├ 成功 → 播放；log voice.tts.ok provider=p.id ms=…
 │         └ 失败 → log voice.tts.fallback from=p.id reason=…; continue
 ├ 4. 全链失败 → 强制 native（native 永不在列表里失败，除非设备无语音包）
 └ 5. native 也失败 → 只显示气泡文字 + 写 voice.tts.dead（用户能看到原因）
```

- **barge-in 策略**：`queue`（默认，排到队尾，最多排 3 条，超出丢最旧）/ `interrupt`（新消息打断当前）。
- **串行队列**：合成与播放各一条 `dispatch_queue_t`，主线程只做 UI。
- **缓存**：`/var/mobile/Library/DSHPet/cache/tts/<hash>.<ext>`，LRU 上限 50MB，面板「素材与存储」里可清（对应 §9.6「清理 TTS 缓存」）。
- **与音乐律动共存**：TTS 播放时律动 `gain` 降到 0.4（避免两套节奏抢动作），播完恢复 —— 见《音乐律动移植清单》第 7 节。

#### 11.7.7 新增一个引擎只要 4 步（这就是可插拔的意义）

1. 新建 `DSHPetTTSProviderXxx.m`，实现 `<DSHPetTTSProvider>` 四个 `@required` 方法；

4. Keychain service 名按 `com.vboxai.littlefatlady.tts.<id>` 约定即可。

4. 同一句连续播 3 次 → 第 2、3 次命中缓存（日志有 `voice.tts.cache=hit`）。
5. 播放中来一条新消息（bargeIn=interrupt）→ 当前立刻停、新的马上播；queue 模式则排队不叠音。
6. 导出诊断包 → 全文搜索无 Key 明文，只有 `sk-***(已配置)`。

### 11.8 屏幕感知（读屏）——第 30 项的详细设计

> 用户问："能自主识别手机上的内容信息并且表达出来，这个又是什么能力？" 业内人士叫 **Screen Understanding / Screen Awareness（屏幕理解 / 屏幕感知）**，属于 **多模态感知 + 大模型推理**，不是"意识"。之前文档只写了"截图→视觉模型→气泡+语音"一行，太薄，这里补成可落地的设计。

#### 11.8.1 三条技术路线（越狱环境三条都能走，推荐混合）

| 路线 | 做法 | 优点 | 缺点 | 何时用 |
|---|---|---|---|---|
| **A · 截图 + VLM** | `_UICreateScreenUIImage()` 截前台 → 缩到长边 1024 → base64 → 视觉模型（`deepseek-vl` / `gpt-4o` 类 / 豆包视觉） | 通用、能理解图表/照片/游戏画面；任何 App 都行 | 慢（1–3s）、贵（token）、有隐私风险 | 图表、看图、UI 看不懂时 |
| **B · 无障碍树** | `UIAccessibility` 遍历前台视图树，拿 label/value/frame → 拼成结构化文本 | **快（<100ms）、几乎零成本、文本准确**（不会 OCR 错） | 拿不到图片语义、Canvas/Flutter/游戏拿不到 | 文字类页面（聊天、股票数字、设置项）优先 |
| **C · 混合（推荐）** | 先走 B 拿结构化文本；若 B 拿到的有效文本 < 阈值（如 30 字）或用户问"这图是什么" → 再走 A 截图 | 兼顾速度与覆盖 | 实现稍复杂 | **默认策略** |

> **越狱红利**：SpringBoard 注入进程可以调私有 API（`_UICreateScreenUIImage`、`UIWindow` 遍历、`AXUIElement` 跨进程），不需要走 ReplayKit 的授权弹窗，也不需要用户手动截屏。

#### 11.8.2 从"看见"到"说出那句股票分析"的完整链路（复刻视频里的效果）

截图里她说的是：

> 「看到啦，中韩半导体 ETF，3.552，涨 1.83%。不过它溢价率 9.17%，等于比自己的净值贵了快一成，跟踪的指数今天还小跌（-0.13%）—— 涨的是价格，不是净值，库。」

这句话**不是 OCR 能直接出来的**，链路是五步：

```
1. 抓取      B 路线的 AX 树拿到：标题"中韩半导体ETF华泰柏瑞"、代码"513310.SH"、
             3.553 / +1.86% / 溢价率 9.27% / 跟踪指数 7557.68 -0.19% / 跟踪误差 5.11%
2. 结构化    抽出 {name, code, price, changePct, premiumPct, indexChangePct, trackingError}
3. 语义推理  交给 LLM（不是视觉模型，是文本模型）：
             溢价率 9% = 价格比净值贵近一成；指数在跌而 ETF 在涨 → 涨的是价格不是净值
4. 人格包装  按人设卡（称呼"爹爹"、口头禅"库…"、语气活泼但会说人话）改写成口语
5. 输出      气泡（流式逐字）+ TTS 语音 + 按 `chatAnimationEnabled` 挑一个说话动作
```

**关键结论**：真正让它"像懂行"的是 **第 3 步的语义推理**，不是分辨率。所以做这个功能**不要把预算全砸在视觉模型上**——文本类内容用 AX 树 + 强文本模型更准更省。

#### 11.8.3 触发方式（三种，缺一不可）

| 触发 | 说明 | 节流 |
|---|---|---|
| **显式** | 用户说"你看看屏幕嘛"/"这写的啥"（STT 命中关键词）；或双击宠物（对应「双击手势=语音输入」） | 无 |
| **定时/切换** | 前台 App 切换后 3s 自动看一眼（可关）；同一 App 内不重复 | 30s 节流 |
| **事件** | 用户点气泡上的「问一下这个」按钮（m01403 里那种悬浮入口） | 无 |

#### 11.8.4 隐私红线（**这条不写会被审核和安全问题打死**）

1. **默认不上传**：只有用户显式开启「屏幕感知」并同意后，才允许把截图/文本发到模型；本地优先用本地模型。
2. **敏感界面自动遮罩**：检测到 `密码 / 支付 / 银行卡 / 身份证 / 验证码 / 输入框 isSecureTextEntry=true / 银行 App bundleId / Apple Pay 面板` → **直接拒绝读，并说明**「这块我不看哈，涉及支付密码」。
3. **不落盘原文**：截图只在内存流转，用完即释放；如必须缓存，放 `NSTemporaryDirectory()` 且 60s 过期。
4. **日志脱敏**：诊断日志只记 `screen.read route=ax chars=NNN app=com.xxx`，**不记内容**。
5. **可一键关闭**：面板「生效范围」里独立开关 + 状态栏提示（读屏时气泡显示一个眼睛图标）。

#### 11.8.5 与「自动操作 App」的关系（第 31 项依赖它）

```
屏幕感知（看）  →  决策（做什么）  →  自动操作（做）  →  再看一眼确认
   11.8                              第 31 项
```

- 读屏是**只读**，安全；自动操作是**写**，危险。
- 自动操作每次动作后必须重新读屏确认（"点了抢，现在到订单页了没"），否则会盲点。
- **支付红线**：读到支付密码/指纹/Face ID 界面 → 立即停止，把控制权交还用户（视频里那句"密码我不敢碰，爸爸自己按还是告诉我？"就是这个逻辑的产品化）。

#### 11.8.6 验收（6 条）

1. 打开股票 App 问"你觉得现在该买吗" → 3s 内气泡逐字出分析，且**引用屏幕上的真实数字**（可对比截图核对）。
2. 打开微信聊天页问"她刚说啥" → 走 AX 路线，<500ms 出结果，不调视觉模型（日志证明 `route=ax`）。
3. 打开支付宝支付页 → 气泡显示「这块我不看哈，涉及支付密码」，日志 `screen.read blocked=secure`。
4. 关闭「屏幕感知」开关 → 再问就答"我眼睛闭着呢，去设置里打开"，不偷偷读。
5. 弱网/模型超时 → 1.5s 内降级为「我只看到标题是 XXX」（AX 摘要），不空转。
6. 导出诊断包 → 搜不到任何屏幕文本原文。

### 11.9 人格与主动交互（"自主意识""自己叫爹爹"）——第 36 项的详细设计

> 用户问："他们有自主意识一样能自己说话，能自己叫爹爹，她这个是属于什么能力啊？" 业内叫 **Proactive / Ambient Agent（主动式智能体 / 伴随式智能体）**，产品层叫 **人格化主动交互**。**它不是意识，是五层工程叠加**。之前我只写了"碎碎念"，没拆层，所以看起来像漏了——现在拆开。

#### 11.9.1 五层拆解（"像有意识"的真相）

| 层 | 作用 | 具体实现 | 是否需要大模型 |
|---|---|---|---|
| **① 人格层 persona** | 决定"她是谁、叫你什么、什么语气" | 人设卡（截图里 QQ 群文件那堆：妹妹版/女友版/私聊版）→ 拼成系统提示词：`用户称呼=爹爹`（面板有「用户称呼」项，截图 m01401 填的就是"爸爸"）、口头禅「库…」、句尾拖音、亲密度语气、禁区 | 否（纯配置） |
| **② 台词层 canned lines** | **"自主说话"的主体，90% 的台词来自这里** | 六类台词包：`clicks`（戳一下：傲娇/害羞/生气 5 类反应）、`whisper`（闲置碎碎念 3 段）、`timeGreet`（早/午/晚问候）、`status`（余额 6 档 / 工作状态 6 态 / 睡觉 3 类）、`sleepTalk`（梦话）、`drag`（被拖动抗议） | **否（本地台词包，零延迟零成本）** |
| **③ 触发层 scheduler** | 决定"什么时候主动开口" | 事件（戳/拖/切换 App）+ 定时（`eventsRefreshSec`）+ **抖动**（±40% 随机，不要精确 300s 一次）+ 静默时段 + 免打扰（前台是游戏/视频时不打扰） | 否 |
| **④ 生成层 LLM**（可选） | 只在"需要接话"时上场 | `/chat` 或自定义供应商（截图 m01401：OpenAI Chat Completions 兼容 + 服务地址 + 模型名 + 温度 2 + 上下文 1000000 + 推理强度 max） | 是 |
| **⑤ 记忆层 memory** | 决定"她记不记得刚才说过啥" | `chatMemoryRounds:10` 轮对话记忆 + 「记忆工作区」（截图里的入口）+ 本地偏好记录 | 是（可选） |

**为什么用户会觉得"有意识"**：① 称呼固定叫你"爹爹" ② 口头禅固定"库…" ③ **主动开口**（不等你问）④ 记得上下文 ⑤ 戳她会有情绪反应（"爹爹…大晚上别戳我嘛…库…"）⑥ 有作息（晚上会困、睡觉拒聊）。

**产品判断**：②③ 做好了，观感就有 80% 的"活物感"，而且**几乎不花算力**。④⑤ 是加分项，但成本高、容易翻车（模型胡说）。所以**先把台词库和触发器做扎实，再接 LLM**。

#### 11.9.2 台词库规格（这是最该先写的东西，比任何模型都重要）

```jsonc
// assets/lines/zh-Hans.json（放素材包，可可热更新）
{
  "version": 1,
  "persona": {
    "callUser": ["爹爹", "爸爸"],          // 随机取，不固定一个
    "petSelf": ["小肥鱼", "库"],
    "tics": ["库…", "…嘛", "欸嘿"],
    "tone": "活泼、爱撒娇、偶尔傲娇、会撒娇但不说脏话"
  },
  "lines": {
    "click": {                              // 戳一下（对应 clicks 5 段动画）
      "happy":  ["欸嘿，戳我干嘛呀", "爹爹今天心情好？"],
      "shy":    ["别、别戳那里啦…库…"],
      "angry":  ["再戳我要生气了哦（鼓脸）"],
      "tickle": ["哈哈哈别挠了别挠了——"],
      "wave":   ["在的在的，我一直在呢"]
    },
    "drag":   ["哇——放我下来！", "飞起来啦——库…"],
    "whisper":[                              // 闲置碎碎念（300s ± 40%）
      "（擦桌子）这桌子怎么又脏了…",
      "（发呆）爹爹在忙什么呢…",
      "（对着屏幕）这个字我不认识欸…"
    ],
    "timeGreet": {
      "morning": ["早呀爹爹，今天也要好好干活哦"],
      "noon":    ["中午了，吃饭没呀"],
      "night":   ["这么晚还不睡…库…我困了"],
      "lateNight":["爹爹…大晚上别戳我嘛…库…"]     // ← 截图原句
    },
    "status": {
      "balanceFull": ["钱袋鼓鼓的，爹爹真会赚"],
      "balanceEmpty":["余额见底了…要不要省着点"],
      "workBusy":    ["我在忙着呢，等我一下下"],
      "workDone":    ["搞定啦！夸我夸我"]
    },
    "sleepTalk": ["唔…别抢我的鱼…", "再睡五分钟…"],
    "sleepRefuse": ["我睡着啦，明天再说嘛…"],
    "edge":   ["（撞到屏幕边）哎哟…"]
  }
}
```

**四个设计要点**（不做这四点就会像复读机）：

1. **同类台词 ≥ 5 条**，随机取且**不连续重复**（记最近 3 条，避开）。
2. **插槽变量**：`{user}`、`{time}`、`{balanceTier}`、`{appName}`，例如"爹爹，都 {time} 了还不睡呀"。
3. **语气分层**：同一事件按亲密度选不同档（生疏/熟络/黏人），随戳击次数与对话轮数升级。
4. **抖动调度**：`下次触发 = 基准 × (0.6 + random×0.8)`，避免整点报时式机械感。

#### 11.9.3 主动开口策略（"不等你问就说话"）

```objc
// 伪代码：每次调度 tick 只做一次判定
- (void)tick {
  if (isQuietHours || isForegroundVideoOrGame || isUserTyping) return;  // 不打扰
  if (now - lastSpokeAt < minGapSec) return;                            // 最小间隔

  double r = random();
  if (r < 0.35 && hasIdleWhisper)      speak(whisper);      // 碎碎念
  else if (r < 0.55 && isTimeBoundary) speak(timeGreet);    // 时段问候
  else if (r < 0.75 && hasStatusEvent) speak(status);       // 状态播报
  else if (r < 0.90 && idleLongEnough) playIdleAction();    // 只做动作不说话
  // 其余：什么都不做（沉默也是表演）
}
```

> **沉默也是表演**：不要每次都说话。10 次调度里 6–7 次什么都不做，才显得"自然"。全说话会变成骚扰。

#### 11.9.4 亲密度（可选，但这是"像活物"的最强杠杆）

| 维度 | 累计方式 | 效果 |
|---|---|---|
| 戳击次数 | 每次 `click` +1 | 台词从"生疏"→"熟络"→"黏人"；动画从"警觉"→"亲近" |
| 对话轮数 | 每次 `/chat` 往返 +1 | 解锁更私人的台词、开始主动关心（"爹爹今天好安静"） |
| 陪伴天数 | 首次启动至今 | 纪念日台词（"认识爹爹第 100 天啦"） |

存 `overrides.jsonc` 里的 `persona.affinity{days, taps, chats}`，面板可看不可改（改了就没意义）。

#### 11.9.6 验收（6 条）

1. 深夜首次戳她 → 出「爹爹…大晚上别戳我嘛…库…」（对应截图原句，说明时段台词生效）。
2. 连续戳 5 次 → 5 条不重复，第 4 次起语气变不耐烦（亲密度/重复抑制生效）。
3. 挂机 10 分钟 → 至少 2 次碎碎念，且间隔不是精确 300s（抖动生效）。
4. 前台播视频 → 全程不说话（免打扰生效）。
5. 关闭「闲置碎碎念」→ 挂机 10 分钟零主动语句，但戳她仍有反应（分层独立）。
6. 换一张人设卡（女友版）→ 称呼与语气整体改变，且不重启 SpringBoard（热重载）。

### 11.11 关键决策：人格靠模型还是靠台词库？（**不是二选一，是分层**）

> 用户问："他不是那种靠模型的人格技能来设定的角色吗？还是说必须要台词库？？" 这是本方案最核心的一个技术取舍，写死在这里，后面不再反复。

#### 11.11.1 先分清两件事

| 问题 | 归属 | 答案 |
|---|---|---|
| "她说话像谁、什么语气、叫你什么" | **内容风格** | 人格技能（系统提示词 / persona 配置）够用，**这就是你说的"靠模型的人格"** |
| "她什么时候开口、戳一下多久有反应、断网还说不说话" | **时机与可用性** | **模型管不了**，这是渲染层与调度层的事，必须有本地台词库 |

**所以不是"必须要台词库"，而是"人格技能和台词库解决的是两个不同问题"**：
- 人格技能决定**说什么像她**；
- 台词库决定**能不能立刻说、永远说得出来**。

#### 11.11.2 纯模型路线能走吗？能，但有四个硬伤

| 硬伤 | 具体表现 | 对桌宠的杀伤 |
|---|---|---|
| **延迟** | 一次 `/chat` 往返 1–3s（含网络+推理） | 戳一下等 2 秒才有反应 → 手感直接死，像卡住 |
| **成本与电** | 一天戳 50 次 + 碎碎念，每次几百 token；SpringBoard 常驻进程持续跑网络 | 电耗、发热、流量，用户会卸载 |
| **离线即哑** | 无网 / 隧道断 / 宿主 DSH 没开 | 桌宠变静态贴纸，"她不理我" |
| **不可控** | 模型会重复、会胡说、会说出戏的话 | 常驻 UI，说错一次用户记一辈子 |

#### 11.11.3 纯台词库行不行？不行

| 硬伤 | 表现 |
|---|---|
| 会复读 | 玩两天所有台词都听过了，一眼假 |
| 不接话 | 你说"今天好累"，她只会播预置的"爹爹辛苦啦"，接不住 |
| 不懂上下文 | 不知道你刚在看股票、不知道余额变了、不记得昨天聊过什么 |

#### 11.11.4 结论：**分层混合**，按"延迟预算"切

| 场景 | 延迟预算 | 走哪条 | 例子 |
|---|---|---|---|
| **触摸反应**（戳/拖/撞边/甩出） | **< 100ms** | 台词库 | "欸嘿，戳我干嘛呀" |
| **被动事件**（时段/余额/待办/工作状态/睡觉） | < 300ms | 台词库（数据靠桥接拉，文案本地） | "都这个点了还不睡呀" |
| **闲置碎碎念/梦话** | 无要求（提前备好） | 台词库 | "（擦桌子）这桌子怎么又脏了…" |
| **主动接话**（你跟她说话） | 1–3s 可接受 | **模型** | "今天股票能买吗" |
| **屏幕理解输出** | 1–3s 可接受 | **模型**（§11.8 第③步） | "涨的是价格，不是净值" |

**第三种玩法（商业桌宠的真实做法，强烈建议）**：**模型离线预生成台词池**——
用模型一次生成 200 条「深夜被戳」的回应，人工过一遍塞进 `lines.json`，热更新下发。
这样**既有多样性，又不用实时调模型**，成本接近零，延迟也是本地级。
每两周重新生成一批，用户永远听不到重复。

#### 11.11.5 证据：两个成熟产品都是混合，不是纯模型

| 产品 | 它怎么做的 |
|---|---|
| **dsh-pet（上游，有模型）** | 有 `/chat` 走模型，但 `sleepStartTexts / sleepEndTexts / sleepRefuseTexts` 仍是 **config 里的本地文本数组**；`events.whisper` 是固定 3 段动画 + 台词包 |
| **大肥鱼（截图那套）** | **两套并存**：人设卡 txt/md（决定"像谁"）+ 供应商设置（OpenAI 兼容 + 模型名 + 温度 + 上下文）；同时有「音色码/说话风格」这类本地可调参数 |
| **dsh-whale-musume-persona（我们查过的仓库）** | 纯模型路线：27KB 配置 + `PERONA.md`，但它**只能让 AI 说话像鲸鱼娘**，管不了"宠物什么时候开口、戳一下怎么动"——因为那是渲染层和调度层 |

**这条证据最关键**：连"纯人格技能"那个仓库，也只是**改了第④层的输入**，它没有、也不可能替代第②③层。

#### 11.11.6 落地顺序（不冲突，先做便宜的那半）

```
第 1 天   30 条台词 + 抖动调度 + 时段/戳击触发  →  立刻能看到"她主动叫你爹爹"
第 2 天   接上供应商（S10-2）→ 需要接话时才调模型
第 3 天   加"模型预生成台词池"脚本 → 台词库自动扩容，摆脱复读
后续      接记忆（chatMemoryRounds）+ 亲密度分档
```

> **判断规则（写死，别再纠结）**：
> **需要"理解语义"才说得出来的 → 模型；只需要"表达情绪/状态"的 → 台词库。**
> 前者占调用量不到 20%，后者占 80%。把 80% 的调用量砍掉，手感和成本同时解决。

#### 11.11.7 面板对应（两类都有开关，用户可自己选倾向）

```
人格
▸ 说话方式
   反应来源     台词库 ▾        （台词库 / 模型 / 混合）
   台词库        [编辑] [重新生成] [导入]
   主动接话      模型 ▾          （关 / 模型）
   连不上时      用台词库兜底 ●
```

# 十二、人格与自主行为系统（Persona OS）· 完整开发规格

> 用户要求：**"要全面的，有台词，又有人格，又能独立有思想的，把整个思路全部写入方案阶段，方便开发。"**
> 本章就是这套系统的**可开工规格**：六层架构 → 内部状态机 → 台词库全量 → 人设卡 → 决策器 → 模型接线 → 记忆 → 离线日程 → 文件划分 → 6 个可独立验收的开发阶段 → 验收 → 附录台词库初版。
> **本章对应 §11 的第 10、11、36 项，并把它们升级成一个独立子系统。**

## 12.1 什么叫"独立有思想"（先把标准定死，否则做不出来）

不是真意识。工程上可验证的"有思想"= 同时满足这三条：

| # | 表现 | 反例（做不到就是假的） |
|---|---|---|
| 1 | **她的反应随内部状态变**：同样被戳，心情好时撒娇、心情差时凶、困了时含糊 | 每次戳都随机抽一条，听完十次就发现没差别 |
| 2 | **她会拒绝**：睡觉时拒绝聊天、忙时敷衍、烦了会炸毛 | 永远有求必应、永远甜 |
| 3 | **她会主动发起**：不等你戳就说话、自己走动、自己找事做 | 只在你操作后才有反应，像台答录机 |

**再加一条隐藏标准**：她的状态要有**连续性**——昨天熬夜导致今天精力低，会被说出来；连续被戳十次会真的生气（不是每次都重置）。

---

## 12.2 六层架构（在 §11.9 五层上加"状态层"，这是"有思想"的根）

```
┌─────────────────────────────────────────────────────┐
│ ⑥ 记忆层 Memory      短期10轮 / 今日摘要 / 长期偏好与纪念日  │
├─────────────────────────────────────────────────────┤
│ ⑤ 生成层 LLM         /chat · 自定义供应商 · 人格提示词注入   │
├─────────────────────────────────────────────────────┤
│ ④ 决策层 Decider     候选行为打分 → 说话/动作/走动/沉默      │  ← "自己想做什么"
├─────────────────────────────────────────────────────┤
│ ③ 调度层 Scheduler   事件 + 定时(抖动) + 免打扰 + 静默时段   │
├─────────────────────────────────────────────────────┤
│ ② 台词层 Lines       12 类台词包 · 插槽 · 去重 · 语气分档   │  ← 零延迟主力
├─────────────────────────────────────────────────────┤
│ ① 人格层 Persona     称呼/口头禅/语气/禁区/人设卡           │
├─────────────────────────────────────────────────────┤
│ ⓿ 状态层 State       mood · energy · affinity · boredom    │  ← 本章新增，核心
│                     focus · activity · 作息相位            │
└─────────────────────────────────────────────────────┘
```

**为什么必须加状态层**：没有状态，台词库只能"随机抽"；有了状态，同一句话在不同状态下有不同含义与不同选法——这就是"像有思想"的全部秘密。

---

## 12.3 内部状态机（State）—— 系统的根，先写这个

### 12.3.1 六个变量

| 变量 | 范围 | 初值 | 含义 | 影响 |
|---|---|---|---|---|
| `mood` 心情 | -100..+100 | +20 | 高兴 / 低落 | 台词语气档、动作选择、是否愿意搭理 |
| `energy` 精力 | 0..100 | 80 | 清醒 / 困 | 动作幅度、语速、是否犯困、台词含糊度 |
| `affinity` 亲密度 | 0..100 | 0 | 陪你多久 | 称呼升级、私人台词解锁、黏人度 |
| `boredom` 无聊 | 0..100 | 0 | 闲置累积 | 主动找你玩、自己找事做 |
| `focus` 专注 | 0..100 | 0 | 你在忙吗（工作状态联动） | 是否打扰你、是否安静待着 |
| `activity` 当前活动 | 枚举 | idle | idle / wander / working / sleeping / dragged / talking / playing | 决定可做什么 |

### 12.3.2 状态转移规则（写死，别每次重新想）

```objc
// 每 tick（默认 1s）执行一次，全部是廉价整数运算，不进网络
- (void)tickState:(double)dt {
    // —— 自然衰减 ——
    self.boredom   = MIN(100, self.boredom + dt * 0.35);          // 每分钟 +21
    self.energy    = MAX(0,   self.energy  - dt * 0.06);          // 每小时 -3.6
    self.mood      = self.mood * pow(0.9995, dt);                  // 缓慢回中

    // —— 事件加减 ——
    // 被戳：开心，但连续戳会烦
    // 被拖：小幅掉心情
    // 完成待办 / 余额上涨：+心情
    // 你说"乖"/夸她：+心情 +亲密度
    // 长时间没人理：-心情（>30min 无交互）
    // 睡觉：energy 快速恢复

    // —— 阈值进入特殊状态 ——
    if (self.energy < 25)                 self.drowsy = YES;       // 犯困：动作变慢、台词含糊
    if (self.boredom > 75 && self.focus < 40) self.wantPlay = YES; // 想找你玩
    if (self.mood < -40)                  self.grumpy = YES;       // 炸毛：台词变凶
    if (self.isSleepHours)                self.activity = Sleeping;

    // —— 作息相位（见 12.9）——
    self.phase = [self currentPhase];      // dawn/morning/noon/afternoon/evening/lateNight
}
```

### 12.3.3 情绪四象限 → 台词档位映射

| mood | energy | 状态名 | 台词档 | 动作倾向 |
|---|---|---|---|---|
| 高 | 高 | **元气** | `tone.genki` | 跳跃、挥手、跑来跑去 |
| 高 | 低 | **慵懒撒娇** | `tone.lazy` | 坐着、靠着你、慢动作 |
| 低 | 高 | **炸毛** | `tone.grumpy` | 跺脚、背对你、扭头 |
| 低 | 低 | **蔫了** | `tone.down` | 蹲着、垂头、叹气 |

> **同一个"戳"事件，四象限取四条完全不同的台词**。这一步做到，观感立刻从"复读机"变"活的"。

### 12.3.4 持久化

- 状态存 `/var/mobile/Library/DSHPet/state.json`，**每 30s 或每次重要事件后落盘**（不要每秒写盘）。
- 冷启动读回；`energy` 按离线时长折算（离线 8h = 睡了一觉，energy→满）。
- 上限保护：文件损坏 / 缺字段 → 回默认值，不崩（沿用 `DSHPetJSONSafe` 的保命思路）。

## 12.6 决策器（Decider）——"她自己想做什么"

### 12.6.1 每次调度 tick 做的事

```objc
- (void)decide {
    NSArray<DSHPetCandidate *> *cands = [self buildCandidates];  // 候选行为
    DSHPetCandidate *best = nil; double bestScore = 0;
    for (DSHPetCandidate *c in cands) {
        c.score = c.baseWeight
                * [self stateMultiplier:c]      // 状态加权（饿/困/无聊）
                * [self timeMultiplier:c]       // 作息加权（深夜压低）
                * [self interruptPenalty:c];    // 免打扰惩罚
        if (c.score > bestScore) { bestScore = c.score; best = c; }
    }
    if (bestScore < kSilenceThreshold) { [self doNothing]; return; }  // ← 沉默也是决策
    [self execute:best];
}
```

### 12.6.2 候选行为与权重基线

| 候选 | baseWeight | 状态加权逻辑 |
|---|---|---|
| 说一句碎碎念 | 1.0 | `boredom/100`，`focus` 高时 ×0.2 |
| 做个小动作（无尽动作库） | 1.2 | `energy/100` |
| 走动 / 换位置 | 0.8 | `energy>40` 才允许，`focus` 高时 0 |
| 主动找你玩 | 0.5 | `wantPlay` 时 ×3 |
| 打个哈欠/犯困 | 0.3 | `drowsy` 时 ×5 |
| 睡觉 | 0.2 | 到睡觉时段 ×10 |
| 看着屏幕发呆 | 0.6 | — |
| 什么都不做 | — | 分数低于阈值即沉默 |

### 12.6.3 沉默阈值（关键手感参数）

`kSilenceThreshold = 0.45`。效果：**约 6–7 成 tick 什么都不做**。
> 调低（0.25）→ 变话痨骚扰；调高（0.8）→ 变高冷死物。0.45 是甜点，面板可调（叫"活泼度"）。

## 12.7 模型接话（LLM 接线，"有思想"的上层）

### 12.7.1 只在三类时刻调用（其余全走台词库）

1. 用户主动跟她说话（STT / 输入框 / `/chat`）。
2. 用户问屏幕内容（§11.8 第③步）。
3. 用户问"你怎么了/你在想什么"——需要引用内部状态时。

### 12.7.2 系统提示词模板（把状态注入，这就是"她有想法"的来源）

```
你是「{name}」，住在用户手机里的桌宠。
{persona正文}

【当前状态】（这些是你真实的身体和心情，说话要符合它）
- 现在 {phaseText}，你有点{energyText}
- 心情{confidenceText}
- 你和{user}认识 {days} 天，亲密度{affinityText}
- 你刚刚在{activityText}
- {focusText}

【说话规则】
- 一到两句话，最多 40 字，不要长篇大论
- 句尾可带"嘛""呀""库…"，但不要每句都用
- 累的时候句子变短、含糊；心情差时要显出来，不要假装没事
- 不许提"我是 AI""我是模型"；不许解释设定
- 不知道就说不知道，别编

【禁忌】{taboo}
```

**注意**：`【当前状态】` 那六行是核心。**同一个问题，在"困"和"元气"两种状态下回答完全不同**——这就是"有思想"的工程实现。

### 12.7.3 调用纪律

| 项 | 值 |
|---|---|
| 超时 | 8s（长轮询不适用，这是对话） |
| 失败降级 | 1 次重试 → 用台词库 `edge.modelFail` 回应 |
| 上下文 | 最近 10 轮（`chatMemoryRounds`） |
| 输出上限 | 120 token（`maxTokens`） |
| 温度 | 0.9（要有人味，不要机械） |
| 语气后处理 | 去掉 Markdown、去角色前缀、超 3 行截断（沿用 §21.3 清洗规则） |

## 12.12 验收清单（12 条，全过才算这套做完）

1. **不复读**：连续戳 20 次，无一条重复；同一事件在四种情绪象限下台词明显不同。
2. **有拒绝**：深夜戳她 → `sleepRefuse`（"我睡着啦，明天再说嘛…"），不是甜言蜜语。
3. **有连续性**：连戳 10 次后 mood 掉档，第 11 次台词变凶；隔 1 小时再来恢复。
4. **有主动**：挂机 15min，主动开口 2–4 次，间隔不是固定值。
5. **有作息**：22:30 后自动进 Sleeping，白天精力高动作幅度大。
6. **有记忆**：第 2/7/30 天启动有里程碑台词；能说出"你昨天很晚才睡"。
7. **状态注入生效**：问"你怎么了" → 回答引用真实 energy/mood，而非通用回复。
8. **离线可用**：断网状态下戳/拖/碎碎念全正常，只有对话降级为 `edge.modelFail`。
9. **不打扰**：前台播视频 / 用户打字 / 免打扰时段 → 零主动语句。
10. **性能**：状态机 + 决策器每 tick < 1ms，主线程占用增量 < 1%。
11. **鲁棒**：台词库 JSON 损坏 / 人设卡解析失败 / state.json 缺字段 → 全部回落默认，不崩、不静默。
12. **可配置**：面板能改活泼度（沉默阈值）、主动说话开关、记忆轮数、人设卡；改完即时生效。

# 十三、语音输出系统（TTS 出声 · 口型同步 · 音效）

> **来源**：m00001 那段 79s 点外卖录屏的音频取证——65.4–77.8s 检出真实人声，vosk 逐词转写与气泡文案**逐字吻合**（65.37「订单」→77.82「告诉我」，置信度 0.92–1.00；两处同音误识「输/枢」「扣/靠」），F0 中位数 **342.6 Hz**（p10 245.4 / p90 398.8）→ 女声，且与气泡逐字同步出现。
> **结论**：小肥娘**不是「只会弹字的贴纸」，而是会出声的角色**。这条能力之前只写了一句「TTS」，不够开发，本章写全。

## 13.1 先拆清楚：语音输出是四件事，别混成一件

| # | 件 | 负责什么 | 做错的后果 |
|---|---|---|---|
| 1 | **合成（TTS）** | 文字 → 音频数据 | 没声 / 声音不像女生 / 卡 2 秒才出声 |
| 2 | **播放（Audio）** | 音频 → 扬声器，管会话与打断 | 一说话就把用户的音乐掐了 |
| 3 | **口型与动作同步** | 音频 → 嘴部帧 + 说话手势 | 有声音但嘴巴不动 = 一眼假 |
| 4 | **音效（SFX）** | 戳 / 拖 / 落地 / 甩出 / 撞边的短音效 | 戳一下没反馈；或音效盖住台词 |

> 第 1 件在 §11.7 已设计成**可插拔 Provider**（豆包 / edge / native 三引擎 + 降级链）；本章补第 2、3、4 件，以及四者之间的**协调规则**。

## 13.2 音频会话（AVAudioSession）——最容易翻车的地方

桌宠是**寄生在别人 App 之上的**，音频会话配错就等于抢用户的音响控制权。硬规则：

```objc
// 唯一允许的默认配置：可混音、不打断、不抢焦点
NSError *e = nil;
[[AVAudioSession sharedInstance] setCategory:AVAudioSessionCategoryAmbient
                                 withOptions:AVAudioSessionCategoryOptionMixWithOthers
                                       error:&e];
[[AVAudioSession sharedInstance] setActive:YES withOptions:0 error:&e];
```

| 场景 | 正确做法 | 错误做法（会被用户投诉） |
|---|---|---|
| 用户正在放歌 | `Ambient + MixWithOthers`，人声与歌**同时响**；台词短（<3s）可以直接叠 | 把音乐暂停/淡出，说完再放 |
| 台词较长（>3s）或念屏幕内容 | 用 `duckOthers`（音量降到 0.3），说完自动恢复 | 一直 duck 不恢复 |
| 用户来电 / Siri / 闹钟 | 监听 `AVAudioSessionInterruptionNotification`，**立即静音当前语音**，结束后**不自动续播**（避免打断通话后果） | 中断后自动恢复，插进通话里 |
| 静音开关拨到静音 | **默认遵守**（`Ambient` 天然遵守静音键），面板提供「忽略静音键」开关 | 强制外放 |
| 未接耳机时 | 正常外放 | 检测到耳机才出声（桌宠不该这么矫情） |
| 音量 | 跟系统媒体音量走，**不改** `MPVolumeView` | 自己调系统音量 |

**中断处理骨架**（照抄）：

```objc
- (void)audioSessionInterrupted:(NSNotification *)n {
    UInt32 type = 0; NSUInteger sz = sizeof(type);
    [[n.userInfo valueForKey:AVAudioSessionInterruptionTypeKey] getValue:&type size:sz];
    if (type == AVAudioSessionInterruptionTypeBegan) {
        [self stopSpeakingNow];            // 立刻停，不淡出（通话中淡出更怪）
    } else {
        [self reactivateSessionIfNeeded];  // 只重激活会话，不重播
    }
}
```

> **真机坑**：SpringBoard 注入的进程没有自己的 `Info.plist`，**不能**依赖 `UIBackgroundModes`；`AVAudioSession` 激活失败要吞掉并降级到「只出气泡不出声」，日志记 `voice.session-fail`，**绝不能让异常冒泡**（SpringBoard 崩溃 = 安全模式）。

## 13.3 说话时的动画：三态机

嘴里有声音的时候，身体必须配合，否则「有声 + 静止」比没声更假。

```
IDLE ──speakBegin──▶ TALKING ──speakEnd──▶ IDLE
                        │
                        ├─speakBegin(新)─▶ TALKING（打断，不重启）
                        └─dragBegin────▶ DRAGGED（语音继续，动作让位）
```

| 状态 | 动画 | 说明 |
|---|---|---|
| `TALKING` | 复用 `clicks` 桶里的「说话手势」（上游 114 段里有 2–3 段可当 talk 用），循环播放 | 没有专用 talk 素材时，退化为 `idle` + 头部轻微点头（±2pt，1.2s 周期） |
| 说话结束 | 回 `idle`，**不硬切**，用 0.18s 交叉淡化 | 硬切会闪一帧 |
| 被拖拽时说话 | 保持 `dragged` 素材，**只播声音** | 一边被拎着一边挥手很怪 |

**与音乐律动的互斥**（§10.5 那条）：正在跟着歌摇摆时收到台词 → **切 `TALKING`，说完回 `DANCING`**，不是两个动作叠加。

## 13.4 口型同步：三个方案，按素材条件选

| 方案 | 原理 | 精度 | 成本 | 什么时候用 |
|---|---|---|---|---|
| **A 音量驱动**<br>（推荐兜底） | 安装 `installTapOnBus` 拿实时 PCM，每 40ms 算 RMS → 映射到 3 档口型（闭 / 半开 / 全开） | 中（嘴动得对，但音素不准） | 低，纯本地 | 任何 TTS 都能用，**默认走这条** |
| **B 时长均分** | 按字数比例把总时长切片，轮流切口型帧 | 低（像木偶） | 最低 | 只有音频、拿不到 tap 时 |
| **C 时间轴/viseme** | TTS 返回时同时给音素或字幕时间轴（豆包 2.0、讯飞有 viseme 输出） | 高（对得上音） | 中，要解析返回 | 豆包引擎且返回带时间轴时**优先用 C** |

```objc
// A 方案核心：40ms 一跳，三档口型
- (void)installMeterOnPlayer:(AVAudioPlayer *)p {
    AVAudioSession *s = [AVAudioSession sharedInstance];
    [p setMeteringEnabled:YES];                        // 最省事的等效实现
    self.meterTimer = [NSTimer scheduledTimerWithTimeInterval:0.04 repeats:YES block:^(NSTimer *t) {
        [p updateMeters];
        float db = [p averagePowerForChannel:0];        // -160..0
        CGFloat f = (db + 45.0) / 45.0;                 // -45dB 以下算静音
        f = MAX(0.0, MIN(1.0, f));
        NSInteger idx = f < 0.15 ? 0 : (f < 0.55 ? 1 : 2);  // 闭/半开/全开
        [self showMouthFrame:idx];
    }];
}
```

> **素材要求**：口型帧 3 张（`mouth_closed / mouth_half / mouth_open`），128×128 透明 PNG 即可，叠在头部锚点上。PetDFY 那套 `anchors` 里有 `bubble:[140,24]`、`tears` 等挂点，**新增 `mouth:[144,96]`** 一类锚点即可复用同一套坐标系。

## 13.5 音效（SFX）：和台词抢声道的问题

| 事件 | 音效 | 规则 |
|---|---|---|
| 单击 / 戳 | `tap.wav`（80ms 轻响） | 与语音**可叠**，但语音播放中把 SFX 音量压到 0.4 |
| 拖起 | `pickup.wav` | 立即响，不等语音 |
| 落地 / 甩出撞边 | `land.wav` / `bump.wav` | 带 `DSHPetHaptics` 震动（低电量不震） |
| 说话开始 | 可选 `chime.wav` | **默认关**（多余） |

```objc
// 音效池：预加载成 AVAudioPlayer 数组，随机取一个未在播的，避免连点叠成噪音
- (void)playSFX:(NSString *)name volume:(float)v {
    if (v <= 0.01f) return;
    NSMutableArray *pool = self.sfxPool[name];
    for (AVAudioPlayer *p in pool) {
        if (!p.isPlaying) { p.volume = v; [p play]; return; }
    }
}
```

**三条硬规则**：①SFX 与 TTS 用**同一个 AVAudioSession**（否则一激活就互相踢）②语音在播时 SFX 音量 ×0.4 ③连续同类 SFX 间隔 < 120ms 直接丢弃（防连点爆音）。

## 13.6 音色、语速、音调要跟状态联动（不是常量）

§12 那套状态机不是只影响台词**内容**，还要影响**怎么念**：

| 状态 | 语速 | 音调 | 音量 | 效果 |
|---|---|---|---|---|
| `energy < 25`（困） | ×0.85 | −2 | ×0.8 | 拖长、懒 |
| `mood > 40`（开心） | ×1.10 | +2 | ×1.0 | 轻快 |
| `mood < −40`（生气） | ×1.00 | −1 | ×0.9 | 硬、短 |
| `lateNight` 相位 | ×0.80 | −3 | ×0.7 | 气声、怕吵醒你 |
| 被拖拽中 | ×1.15 | +3 | ×1.0 | 惊慌 |

映射到 TTS 请求就是现成字段（§11.7 的 `DSHPetTTSRequest`）：`speed` / `pitch` / `volume` / `style`，**逗音色不变，只调参数**——换音色会让人格崩掉。

## 13.7 文本预处理（决定听起来像不像人）

台词进 TTS 之前必须过一遍，否则会念出机器味：

| 输入 | 处理 | 为什么 |
|---|---|---|
| `库…` / `唔…` / `欸嘿` | **保留**（语气词，是人设的一部分） | 删了就没灵魂 |
| `{user}` 已渲染为「爹爹」 | 保留 | 称呼必须念出来 |
| `¥3.33` | → `三块三毛三` | TTS 会念成「人民币三点三三」 |
| `1.83%` | → `百分之一点八三` | 否则念「一点八三百分号」 |
| `513310.SH` | → `五幺三三幺零`（逐位） | 代码要逐位念 |
| 长句 > 40 字 | 在逗号/破折号处切两段，段间 120ms | 一次念 60 字会喘不上气 |
| 括号内容 `（小声）` | 剥离，转成 `style` 参数 | 不该念出来 |
| 表情符号 / `库…`(省略号) | 省略号转 200ms 停顿 | 念「点点点」很蠢 |

## 13.11 验收清单（10 条，逐条可真机验证）

1. 断网、无 Key：仍能出声（native 兜底），日志有 `voice.fallback=native`。
2. 豆包 Key 填错：气泡照常出，声音退回 native，**不弹窗不崩溃**。
3. 正在放 Apple Music：说话时音乐**不断**（Ambient + MixWithOthers 生效）。
4. 念超过 3s 的长句：音乐被 duck 到 0.3，说完 **1s 内恢复**。
5. 来电：语音**立刻静音**，挂断后**不自动续播**。
6. 静音键拨下：默认无声；打开「忽略静音键」后有声。
7. 连续点 10 下：不叠音（同一时刻只有 1 路 TTS），SFX 不爆音。
8. 边被拖拽边说话：动作保持 `dragged`，只有声音。
9. 说话时嘴巴动（三档口型至少能看出开合），说完 0.2s 内闭嘴。
10. 同一句话重复 20 次：命中缓存，第 2 次起**延迟 < 50ms**。

## 13.12 真机坑（写下来避免重踩）

| 坑 | 现象 | 解法 |
|---|---|---|
| `AVAudioPlayer` 播放前没激活会话 | 第一次说话没声音，第二次才有 | `speak` 入口统一 `setActive:YES` |
| `AVAudioSessionCategoryPlayback` | 一说话**把用户的歌掐了**，还被系统判为抢占 | 必须 `Ambient` |
| `AVSpeechSynthesizer` 与 `AVAudioPlayer` 混用 | 音色切换时互相打断、delegate 收乱 | 同一时刻只用一个引擎，切换前 `stopSpeakingAtBoundary:Immediate` |
| 内存里建 `AVAudioPlayer` 不释放 | 说话 200 次后 SpringBoard 被 jetsam 干掉 | 播完置 nil，缓存只留文件 |
| 音效与语音各建一个 session | 一激活就互相 deactivate，声音断续 | 全局一个 session，统一管理 |
| `installTapOnBus` 忘记 `removeTap` | 第二次播放 crash（bus 已占用） | 停播时 `removeTapOnBus:` 并置 `nil` |
| 在 SpringBoard 里调 `AVAudioSession` 出错抛异常 | 安全模式 | 全部 `@try/@catch` + 日志吞掉 |

> 本章补的是之前**真正漏掉的一块**：前面 §10 只写了"桥接会话状态"，§12.7 只写了"什么时候该调模型"，但**怎么连模型、连谁、Key 放哪、回复怎么落地**一直没写。你截图里那套「供应商设置」（OpenAI 兼容 / 服务地址 / 模型名 / 温度 / 上下文）属于这一章。
>
> 一句话：**§12 决定"什么时候说"，本章决定"说得出来"。**

## 14.1 现状与缺口（先认账）

对现有代码做全仓 grep，结论很直接：

| 检查项 | 结果 |
|---|---|
| `grep chat / completions` | 只命中 `DSHPetEventChat`（一个状态机事件常量，值 `@"chat"`，作用只是 mood +3） |
| `grep apiKey / provider / temperature` | 无 |
| `DSHPetBridge` 实际端点 | 只有 `GET /dsh-pet-7340/state` 与 `GET /dsh-pet-7340/todos` |
| 面板 | 6 组，无任何 AI 相关项 |

**所以现在这个插件不会说话（指"生成式对话"），只会念台词库。** 本章就是补这条路。

## 14.2 三种接法，选 B 为主、A 为备

| 方案 | 做法 | 优点 | 缺点 | 取舍 |
|---|---|---|---|---|
| **A 走宿主** | 调宿主 dsh-pet 的 `/chat`，Key 由宿主管 | 手机端零 Key、零配置 | 宿主必须在线（隧道通）；上游 `/chat` 语义是"会话助手"，不一定接受人格化短句 | **作为免配置默认** |
| **B 直连** | 面板填 baseURL / model / Key，直连 OpenAI 兼容服务 | 不依赖宿主；可换任意模型；可本地局域网（如 `192.168.1.230:3425`） | 要自己管 Key、自己算成本 | **主路线** |
| C 端侧小模型 | 打包 gguf + llama.cpp | 完全离线 | iOS 越狱机跑 4B 级模型：内存 2–3GB、首字 3–8s、SpringBoard 里跑会被 jetsam 杀 | **不做**（写在这里是为了以后别再讨论） |

**默认顺序**：面板里 `aiProviderOrder = ["direct", "host"]`。直连没配 Key 就回落宿主；宿主也 404 就静默走台词库。

## 14.3 配置项全表（面板第 7 组就照这个建）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `aiEnabled` | bool | `NO` | 总开关。**默认关**——不配就用台词库，谁都不会因为它偷偷上网 |
| `aiProvider` | choice | `direct` | `direct` 直连 / `host` 走宿主 |
| `aiBaseURL` | text | 空 | 例：`http://192.168.1.230:3425/v1`（本机局域网）或 `https://api.deepseek.com/v1` |
| `aiModel` | choice | 空 | **从 `/models` 动态拉，禁止硬编码**（上游 55 方法对账 §19.2 结论） |
| `aiAPIKey` | keychain | 空 | 只写 Keychain，永不进 plist / 日志 / 崩溃报告 |
| `aiTemperature` | choice | `0.9` | 0.3 / 0.6 / 0.9 / 1.2。桌宠要有人味，别用 0 |
| `aiMaxTokens` | choice | `120` | 60 / 120 / 200 / 400。**气泡装不下就得截断，所以宁可短** |
| `aiContextRounds` | choice | `10` | 0 / 5 / 10 / 20。0 = 不带上文（最省钱） |
| `aiTimeoutSec` | choice | `8` | 5 / 8 / 15 / 30 |

## 14.4 模型发现：两级下拉，不许写死

```
面板「模型名」点进去
  ├─ 拉 GET {baseURL}/models  （超时 5s，失败给"手动输入"入口）
  ├─ 按 vendor 前缀分组：deepseek-* / qwen-* / gpt-* / claude-* / 其它
  └─ 选中后写 aiModel
```

三条纪律：

1. **不许 code 里写死 `deepseek-chat` 之类的名字**——模型会改名、会下线（上游 §19.2 就是因为硬编码才 404）。
2. 拉不到列表时**不报错**，只把输入框切成可手填，并在下面灰字提示"服务未返回模型列表，可手动填写"。
3. 记住上次成功的 `(baseURL, model)` 组合，下次换 baseURL 时若模型不匹配就清空，避免 400 循环。

## 14.5 Key 存放：Keychain，不是 plist

| 项 | 做法 |
|---|---|
| 存储 | `SecItemAdd` / `SecItemUpdate`，service `com.vboxai.littlefatlady.ai`，account = `aiAPIKey` |
| 读取 | 每次请求前取一次（不缓存到内存变量超过一次调用） |
| 删除 | 面板输入框**留空保存 = 删除**（对齐你截图里那句"留空保存可删除"） |
| 展示 | 只显示 `已配置（尾号 XXXX）` / `未配置`，**永不回显完整 Key** |
| 日志 | 只记 `key=set` / `key=unset` / `key=missing`，任何分支都不许把 Key 拼进字符串 |
| 崩溃 | Keychain 读取失败 → 视为未配置，回落台词库，**不许断言、不许抛** |

> 为什么不用 plist：`/var/mobile/Library/Preferences/*.plist` 是明文，且在 rootless/roothide 下会被各种备份工具抓到。Keychain 是唯一像样的选择。

## 14.6 提示词装配（这是"像她"的关键）

每次请求的 messages 组装顺序固定，不要随意调整：

```
[system]  ┌ 人设卡正文（§12.5 的 persona md）
          ├ 【当前状态】六行（这就是 §12 状态机的出口）
          ├ 【说话规则】短、口语、不超过 40 字、不用 markdown、不用括号动作
          └ 【禁止】不索要密码/验证码/身份证；不输出网址；不提"我是AI"
[user]    用户原话（或"你看一下屏幕"这类指令）
[history] 最近 N 轮（N = aiContextRounds，超过就丢最早的）
```

【当前状态】六行的实际内容（由 `DSHPetState` 直接给）：

```
【当前状态】
时段：深夜      （凌晨 2 点）
精力：23/100    （很困）
心情：-15       （有点蔫）
已陪伴：37 天
亲密度：62/100  （熟人）
正在做：发呆
```

**为什么这六行比任何提示词工程都重要**：同一句「你怎么了」，精力 90 时她答"没事呀，就是有点想戳你"，精力 20 时她答"困……别闹"。没有这六行，模型只能给通用回答，两天就腻。

## 14.7 回复后处理（模型输出不能直接用）

| 步骤 | 处理 | 原因 |
|---|---|---|
| 1 | 去 markdown（`**`、`#`、`` ` ``、列表符） | 气泡是纯文本 UILabel，星号会原样显示 |
| 2 | 去括号动作（`（笑）`、`*歪头*`） | 没有对应动画就别说，说了出戏 |
| 3 | 去 AI 味开头（"作为一个AI"、"我理解你的感受"） | 直接命中人格禁忌 |
| 4 | 超 40 字按句号/问号切段，只留前 1–2 段 | 气泡上限，多了溢出 |
| 5 | 命中禁词（密码/验证码/转账/卡号）→ **整句丢弃**，改播台词库的 `edge` 类 | 安全兜底 |
| 6 | 交给 §13.7 的 TTS 预处理 | 金额、百分比、数字要读对 |
| 7 | 气泡走 `DSHPetSayNotification`，语音走 `DSHPetVoice` | 与现有链路一致 |

## 14.8 多模态（图片）：默认关，且只发必要的那一张

- 只在 §11.8 的"问屏幕"分支启用；普通聊天**不带图**。
- 压缩：长边 ≤ 1024、JPEG q0.7、单张 ≤ 300KB，一次最多 1 张（面板上限 4 张是硬限制，不是建议值）。
- base64 塞 `image_url` 字段，`detail: "low"` 起步；看不清再升 `high`。
- **绝不自动发**：必须由用户明确触发（长按菜单 →「看看屏幕」）。

## 14.9 不做流式

桌宠气泡的"逐字打出"是**本地打字机动画**，不是模型流式返回。理由：

- 流式要在 SpringBoard 里维持一条长连接 + 增量解析，收益是"首字快 0.5s"，代价是复杂度和出错面翻倍；
- 气泡本来就只显示 40 字，等 1–2 秒整段出来，配合打字机效果，观感已经够。

**结论：`stream: false`，一次拿全。** 想更快就换近一点的 baseURL（局域网）。

## 14.10 错误矩阵（每个分支都要有确定动作，不许空白）

| 情况 | 判定 | 动作 | 用户看到 |
|---|---|---|---|
| 未配置 Key | 本地 | 回落宿主 → 台词库 | 正常说话（台词库） |
| 401 / 403 | HTTP | **不重试**、清标记、提示一次 | 台词库；面板里那行变红"Key 无效" |
| 404 on /models | HTTP | 切手动输入 | "服务未返回模型列表" |
| 400 | HTTP | 记 body 前 200 字到日志 | 台词库 |
| 429 | HTTP | 读 `Retry-After`，冷却期内不调 | 台词库 |
| 5xx | HTTP | 重试 `aiMaxRetry` 次（间隔 1s、2s） | 台词库 |
| 超时 | NSError | 不重试（等太久已没意义） | 台词库 |
| 断网 | `NSURLErrorNotConnectedToInternet` | 标记离线，5 分钟内不再试 | 台词库 |
| 返回空 / 全是符号 | 后处理 | 当失败 | 台词库 |
| Token 超预算 | 本地计数 | 当天剩余时间只走台词库 | 台词库 |

> **统一原则：任何 AI 故障都不许打扰用户。** 桌宠不该弹"网络异常，请检查设置"——它只会"安静地用自己的话回答"。

## 14.11 成本与配额

- 每次请求后按 `usage.total_tokens` 记账，落 `/var/mobile/Library/DSHPet/ai/usage-YYYYMMDD.json`。
- 跨天清零；`aiDailyTokenBudget` 到了就停用 AI（面板里显示"今日额度已用完"）。
- 粗算：一句 40 字回复 + 10 轮上下文 ≈ 800–1500 tokens。一天聊 30 句 ≈ 3–5 万 tokens，所以默认 5 万是"够用但不会失控"的量级。
- **不聊天就不花钱**：状态注入与主动开口全走台词库，不产生调用。

## 14.12 隐私红线（写死，不许谈判）

1. 默认 `aiEnabled = NO`，不配不联网。
2. 不上传屏幕，除非用户当次明确点「看看屏幕」。
3. 对话原文只存最近 7 天（§12.8 的中期记忆），长期记忆只存摘要。
4. Key 只存在本机 Keychain，任何日志/崩溃/导出都不含。
5. 面板必须提供「清除全部对话记录」与「清除 Key」。

## 14.15 验收 12 条

1. 不配 Key：插件完全不联网，仍能说话（台词库）。
2. 配错 Key：面板显示"Key 无效"，气泡里**不出现**任何错误字样。
3. 断开网络：5 分钟内不再重试，不耗电。
4. 局域网 `http://` 地址可用（ATS 例外只对这一条路径开）。
5. `/models` 拉不到时能手动填模型名并成功对话。
6. 同一句「你怎么了」，精力 90 与精力 20 的回答明显不同。
7. 模型回复里出现 `**加粗**`、`（笑）`、`作为一个AI` 时都被清洗掉。
8. 回复超过 40 字时只保留前 1–2 段，不溢出气泡。
9. 模型回复提到"密码/验证码"时整句被丢弃，改播 `edge` 台词。
10. 日额度用完后自动停用 AI，面板显示已用完，不说话也不报错。
11. 连续 20 轮对话后上下文不无限增长（严格按 `aiContextRounds` 截断）。
12. 清除 Key 后立刻回落，且 Keychain 项确实不存在（可用 `security` 验证）。

**避让为什么要"推"而不是"放弃"**：放弃看起来像卡住——想往右走、右边正好有气泡，于是原地不动，体感是"她坏掉了"。推到最近一侧至少还在动，用户看不出是被避让规则改过路径。

**下一批（按我给的排序继续）**：纵向分区 + 悬停模式（1.5 人日）。难点不在分区，在于**纵向位置会被物理层抢**：

- 现在 `center.y` 归物理（重力、落地、反弹）所有；让行走改 y，两边会打架，表现是"每帧被拉回地面"或"悬在半空抖动"。
- 正确做法是先给物理层加一个「悬停模式」：`floatMode=YES` 时跳过重力积分与落地判定，只保留拖拽与边界约束；行走才接管 `center.y`。
- 悬停模式本身也是产品能力（§11 的「原地漂浮踏步」动作就是这么播的），所以这一步不算为分区硬造。


## 十六、严重故障复盘：装完插件过一会儿，打开任何 App 都卡在启动页

> 发生时间 2026-11-19。真机 iPhone 14 Pro / iOS 17.0 / Relaxin。现象：安装插件并运行一段时间后，任意 App 启动都停在启动页不动，必须硬重启。

### 16.1 根因（不是"越狱不稳"，是我们自己的代码）

`DSHPetBoot.m` 的 `DSHPetLog()` 里，把**一次性初始化**和**每条日志**写在了同一个函数体里：

```objc
void DSHPetLog(...) {
    createDirectoryAtPath  ×3          // 每条日志
    contentsOfDirectoryAtPath(assets)  // 每条日志，扫整个目录
    removeItemAtPath ×N                // 每条日志，逐个判断要不要删
    fileExistsAtPath ×6                // 每条日志
    open / seekToEnd / write / close   // 每条日志
}
```

而 `DSHPetLog` 的调用点多在**高频路径**上：物理 settle、行走 begin（每 6–16 秒）、点击、气泡、调度 tick。合起来是**每秒几十次同步文件元数据操作，全在 SpringBoard 主线程**。

SpringBoard 主线程负责把前台 App 推过启动页。它被同步 I/O 占满之后，进程还在、界面不响应，表现正是"卡在启动页"。日志文件还在无界增长（`seekToEnd` 追加），越写越慢，所以是"过一段时间才犯病"，不是"一装就崩"。

**教训（写死在这里）**：`DSHPetLog` 是"一条路径"，不是"一个初始化入口"。任何带目录扫描、删除、`dispatch_once` 语义的东西都不许出现在日志函数里。高频路径上的磁盘操作必须满足两条：① 一次性语义用 `dispatch_once` 圈死；② 写盘一律丢后台队列。

### 16.2 修复（S-FIX1，commit c3a013c2 / 59c00ad8 / 6193df43）

| `DSHPetBoot.m` | 目录创建 / 素材自检 / doctor / 残留清理全部收进 `DSHPetLogSetupOnce()`（`dispatch_once`）；JSON 序列化留调用线程（便宜），**写盘改到串行后台队列**；每 200 条查一次大小，超 512KB 轮转为 `.1`，日志不再无界增长 |

### 16.3 用户侧急救步骤（按顺序试）

1. **硬重启**：音量+ → 音量− → 长按电源键。重启后越狱环境未加载，**插件不生效，系统恢复正常**。
2. 重新越狱（Relaxin）后，**不要等 SpringBoard 稳定**，任选其一：
   - Filza 建空文件 `/var/mobile/Library/DSHPet/disabled` —— 插件启动时看到它就完全禁用自己；
   - 或 Sileo 直接卸载 `com.vboxai.littlefatlady`。
3. 若连 Filza/Sileo 都进不去：在 Relaxin 里关掉 Tweaks 注入后再越狱，进去卸载。
4. 顺手删掉 `/var/mobile/Library/DSHPet/logs/` 下的旧日志（可能已有几百 MB）。

### 16.4 以后怎么避免同类问题（三条硬规矩）

1. **日志函数里只允许"组装 + 入队"**，不许任何目录扫描、删除、`createDirectory`。
2. **所有写盘走串行后台队列**，主线程不碰文件句柄。
3. **日志必须轮转**，否则"性能问题"会伪装成"偶发卡死"，极难定位。
